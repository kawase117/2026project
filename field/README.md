# field/ — 手入力データ

## ここに入れるもの

**台データのスクレイピングでは原理的に取れない情報**だけを置く。

- `specs/` — 機種のスペック表（設定差のある小役確率など）。攻略サイト・雑誌由来の手入力
- `sessions/` — 実戦での手カウント記録（小役回数、カウント区間の回転数）

## ここに入れないもの

ana-slo / site777 から取れるもの（G数・差枚・BB/RB回数・台番号・機種名）は入れない。
それらは `data/`・`db/`・`scraper/site777/output/` にあり、自動で更新される。

## なぜ分けるか

由来が違うと信頼性の性質が違う。スクレイピング由来は「サイトが出した値」で再取得できるが、
手入力は再現できず、転記ミスもカウント漏れも起こる。同じディレクトリに置くと、
どちらの品質問題を疑うべきか分からなくなる。

## 分母の定義（最重要）

**小役のカウント区間の回転数を使うこと。総回転数ではない。**

2026-09-12 の実測で、この取り違えだけで結論が反転した:

| 分母 | 設定1 | 設定2 | 設定5 | 設定6 | 高設定(5+6) |
|---|---|---|---|---|---|
| 2322G（総回転数） | 56.3% | 33.9% | 9.0% | 0.8% | **9.8%** |
| 2076G（カウント区間） | 10.3% | 21.3% | 36.3% | 32.1% | **68.3%** |

差はわずか246G（ボーナス/AT消化分）。小役をカウントできない区間を分母に含めると、
全役のレートが一律に薄まり、低設定と区別がつかなくなる。

セッション記録には必ず `counted_games`（カウント区間）を書く。
`total_games`（総回転数）は参考として別フィールドに置く。

## 使い方

```bash
venv/Scripts/python.exe field/koyaku_setting.py field/sessions/<file>.json
```

スペックを追加するときは `specs/koyaku_specs.json` に機種を足す。
役は `components` に構成要素（スイカA・スイカBなど）を並べ、推定時に合算される。

## 注意

- **2000G程度では設定を断定できない。** 高低比と「否定できない設定の幅」を必ず併記する
  （`feedback-statistical-certainty-calibration`）。
- 推定器は分母への感度を必ず出力する。カウント区間が曖昧なときはその幅で結論が動く。
- 差枚で設定を判定しない（`feedback-scoring-must-separate-setting-from-pnl`）。
