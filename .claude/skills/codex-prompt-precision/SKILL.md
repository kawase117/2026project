# Codex Prompt Precision Skill

## トリガー
- Codex(codex-rescue / codex:rescue)に実装を委任するプロンプトを書く直前
- 「指摘」として severity タグ(高/中)付きで2回以上修正した経験がある種類の依頼をするとき

## 背景
2026-06-12(9dec59e9)で、Codexへの実装委任プロンプトが「load_hall_daily_frame契約の曖昧さ」「CSVスキーマ粒度の不整合」を理由に2回連続で修正させられた。この見直しサイクル自体が毎回発生する固定コストになっている(詳細: `document/mirror_evidence.md` セクション4)。

## 送信前チェックリスト
プロンプトを送る前に、以下4点を自問し、曖昧な項目があればプロンプトに明記してから送信する。

1. **契約の明示**: 関数/スクリプトの入出力の型・単位・NULL/欠損の扱いを明記したか(例: 差枚は円か枚か、日付はJST基準かUTC基準か)
2. **スキーマ粒度の一致**: 参照するテーブル/CSVの粒度(台×日 / 日×機種 / ホール×日など)を明示し、集計単位の取り違えが起きないようにしたか
3. **日付境界の明示**: 「当日」「前日」「翌日」の定義(閉区間/開区間、営業日跨ぎの扱い)を明記したか
4. **交絡・除外条件の申し送り**: 既知の除外対象(鉄台、新台、全設定6の特殊日など)をプロンプトに含めたか

## やること
1. 依頼内容を上記4点でセルフレビューし、曖昧な箇所を先に埋める
2. 埋めた上でなお不明な点があれば、Codexへの依頼文の冒頭に「未確定事項」として明記する(後出しの手戻りより、先出しの確認の方が安い)
3. 修正が実際に発生した場合は、どの項目が漏れていたかを記録し、次回のチェックリスト精度向上に使う
