# Prediction Recheck Skill

## トリガー
- DBに新しい実績データが投入された後
- 「答え合わせをもう一度」「再度確認して」と言いたくなったとき
- 過去に「データ不足で保留」にした予測の答え合わせを再開したいとき

## 背景
2026-06〜07のセッション(198d0d25等)で、新台day0-7戦略の予測→実績確認が、DBの欠損データが埋まるたびに3回以上手動で繰り返されていた。予測ロジックと答え合わせロジックが分離されており、都度Bashで手書きSQLを組み直していたのが repetition tax の最大要因(詳細: `document/mirror_evidence.md` セクション4)。

## やること
1. 対象ホール・対象期間・対象セグメントを確認する(省略時は直近の未確定予測を自動検出)
2. `prediction-evaluation` スキルの評価原則(セグメント別分離・末尾とゾロ目の分離報告・分母を揃えた比較)に従って再集計する
3. 前回実行時との差分(新しく確定した行のみ)を明示する — 全件再計算ではなく増分のみ報告
4. 結果をTop3/Bottom3一致度・hit@3で要約し、外れた場合は原因候補(ノイズ末尾・特定台の突出等)を`prediction-evaluation`のアウトライア検出手順で確認する

## 出力
- 差分サマリ(前回確認時点 → 今回)
- Hit@3 / セグメント別一致度
- 新規に確定したためレビューが必要な行のリスト

## 実装メモ
このスキルは評価ロジックそのものは再定義しない。あくまで「再実行のトリガーと差分報告」を自動化するためのラッパーとして機能する。
