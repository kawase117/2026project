# Mirror Review Skill

2026-07-13に一度実施した「セッション履歴の発掘→蒸留→インタビュー→鏡→レバレッジ→残滓」の6フェーズプロセスを、繰り返し実行できる形にしたもの。初回の実施記録は `document/mirror_evidence.md` / `document/mirror.md` / `document/roadmap.md`。

## トリガー
- ユーザーが定期振り返りを明示的に依頼したとき
- 前回の mirror-review から3ヶ月以上経過し、作業スタイルの変化を確認したいとき
- 大きなプロジェクトの節目(フェーズ完了、方針転換)の後

## 全体構造(6フェーズ、必ず順番通り、フェーズを飛ばさない)

### Phase 1: Excavate(発掘)
- `~/.claude/projects/`, `~/.claude/history.jsonl`, `~/.codex/sessions/` 等、セッションアーカイブの在り処を確認
- 各ソースのファイル数・サイズ・日付範囲を一覧化
- **ゲート**: インベントリと採掘プラン(どのソースをどう抽出するか)を提示し、ユーザーの承認を待つ

### Phase 2: Distill(蒸留)
- 1ファイルあたり最大150行、合計200ファイルまで
- 最新15+最古10+中間20件のようなサンプリングで偏りを抑える
- 生ログをそのまま会話コンテキストに持ち込まない — サブエージェントに委譲し、evidence.mdのみを受け取る
- 出力ファイル名は `document/mirror_evidence_<YYYY-MM-DD>.md` として毎回新規作成し、前回版を上書きしない(比較のため)
- 6セクション必須: recurring_themes / abandonment_graveyard / correction_patterns / repetition_tax / rhythm / blind_spots。すべてに日付+件数+短い引用の受領証を付ける。3回未満の出現は「insufficient data」と明記し、断定しない
- **ゲート**: 全セクションが埋まるまで解釈フェーズに進まない

### Phase 3: Interview(インタビュー)
- 証拠から5つの仮説を立てるが、ユーザーには見せない
- 1問ずつ、ユーザー自身に気づかせる質問を投げ、回答を待つ
- 回答が証拠と矛盾する場合は受領証を示して再度問う。矛盾こそが一番面白いデータ
- ユーザーからの訂正・反論は「間違いだった」と即座に受け入れず、evidence.mdの該当箇所を実際に読み直して判定できるかを確認する。判定できなければ「未解決」と明記する(折れて迎合しない)
- 全5仮説の結果をevidence.mdに追記

### Phase 4: The Mirror(鏡)
- 何を信じているか(時間の使い方で測る、発言ではない)
- 思考がどう速く動き、どこで堂々巡りするか
- 本当に優れていること
- 何を避け、その回避が何を守っているか
- まだ言葉にしていない一点(最も鋭い指摘は最後に一度だけ、繰り返さない)
- 各主張に受領証を付ける。ユーザーが反論したら根拠で応じる(迎合しない)が、根拠が手元にない場合はそれも正直に認める

### Phase 5: Leverage(レバレッジ)
- WASTE(受領証付きで時間が消えている場所)
- DELEGATE(AIに恒久委任すべきこと、回収時間の大きい順)
- FOCUS(本人にしかできない1〜2点)
- DROP(コストのみでリターンが無いもの)
- KEEP(機能しているので守るべきもの)
- RHYTHM(タイムスタンプから見た、深い作業とアドミン作業の最適な時間帯)
- 各項目に具体的な初手アクションを付ける(アクション無き洞察は娯楽)

### Phase 6: Residue(残滓)
- `document/mirror_<YYYY-MM-DD>.md`(半年後に読み返す想定で執筆)
- `document/roadmap_<YYYY-MM-DD>.md`(30日計画)
- CLAUDE.md/AGENTS.mdへの追記提案は必ずdiffで提示し、既存ファイルへの変更は逐一承認を得てから適用する
- 新規スキル提案はまとめて1回の承認でよい
- 前回の mirror-review から継続している課題(例: 「収益化の判定基準がまだ言葉になっていない」等)があれば、今回それが解決したかを明示的に確認する

## 運用上の注意
- 個人情報・APIキー等の機密情報は絶対に引用しない
- 全てローカル完結。外部サービスへのセッションデータ送信は行わない
- 1回しか起きていないことはノイズ、3回以上起きたことが性格、という基準を毎回徹底する
- 過去の mirror.md / roadmap.md と矛盾する結論が出た場合は、変化そのものを明示的に記録する(「以前はXだったが今回はYになっている」)
