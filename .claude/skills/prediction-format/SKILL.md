# 予測文書の形

2026-10-30 制定。根拠は `document/reviews/2026-10-monthly-retrospective.md`(手書きの推しは基準とほぼ同じ成績で上積みが見えない、蒲田7は手書きが基準より下、前日の継続を根拠にした示唆が当たらない、文書が長くなっても精度は上がらない)。
採点は `venv\Scripts\python.exe -m backtest.scoreboard` の「4a. 手書きの推し − 基準」「5. 避ける・開店前の凍結」で見る。11月末に4aの「4ホール合計」が正でなければ、手書きの推しをやめて基準に置き換える。

朝の自動下書き(`scripts/run_morning_docs.py` の `prediction_prompt`)は、下の印の間をそのままプロンプトに埋め込む。**ここを書き換えると翌朝の下書きの形が変わる。**

## 予測の形(ホール節ごと)

1. **基準を最初に載せる。** 基準 `<ホール>_model_term60_top3`(直近60日の機種平均上位3。毎朝 `backtest/forward/` に凍結される)の3機種を、節の最初に `基準: A・B・C` の行でそのまま書く。基準の無いホール(金時・ヒロキ・ARROWなど)は書かない。
2. **判断は基準からの差し替えだけ。** `判断:` の行は基準の3機種の名前から始め(凍結は `判断:` の行に書かれた機種名だけを拾うので、「基準の3機種」とだけ書かず名前を書く)、予告・イベントで足す・外す機種だけに理由を1つずつ書く。外す機種は `判断:` の行に名前を書かない。差し替えが無ければ `判断: A・B・C(基準のまま)。` だけでよい。基準の無いホールは、予告の公約機種だけを推すか、推さない。
3. **予告の外こそ予測する(試験枠)。** 予告に載っているものをなぞるのは予測ではない(ユーザー指摘 2026-10-30)。予告の無い日(全ホール)と、予告のある日の予告外の機種・台は、検証できる方法から候補を出し、`試験枠:` の行に書く。方法は次の3つで、どれも毎朝自動で凍結・採点されるので、手で選び直さない。
   - (a) 基準の3機種(`model_term60_top3`)
   - (b) RB判別機の自動候補(文書末尾の「RB機種候補」の表、`backtest/rb_candidates.py`)
   - (c) 蒲田7のジャグラーは、前日までの持ち越し上位(`backtest.juggler_carryover tomorrow` の候補)を**外す**。10月は候補の台が同じ機種の他の台より −212(15日、上回った日4/15)で、良かった台が下げられている可能性がある(仮説)。外す台を `試験枠:` の行に台番号で書く。
   `試験枠:` の行は凍結で推しとして拾わない。採点表で基準を上回った方法から `判断:` の行に格上げする(格上げはユーザーと決める)。蒲田7は、格上げされた方法が無いうちは、予告の無い日の `判断:` に機種を書かない。
4. **「避ける」は構造の理由だけ。** 機械割の低さ、稼働不足(回転数が伸びず判別できない)、台数の変化(減台・入替)。前日の負け・過去回の負けを理由にしない。構造の理由が無ければ `避ける:` の行は書かない。
5. **台番号は自動候補に一本化する。** 台の名指しは `backtest/rb_candidates.py` の自動候補(文書末尾の「RB機種候補」の表)に任せ、本文で台番号を選ばない。手で台番号を書くのは、予告で台が指定された日だけ(そのときは予告の原文どおりに)。
6. **予告がある日の重みづけ。** 主にするのは、筆頭の名指し・公約機種・先バレ。同じ系列の過去回の成績は従(標本が少ないことを添える)。言葉遊び(日付の語呂・機種名のもじり)から機種を抜き出した推測は、`判断:` の行に入れず、解説に「参考」として書く。
7. **前日の結果を根拠にしない。** 前日に強かった機種・末尾・列が翌日も続く、という根拠は使わない(継続は10月の答え合わせで何度も否定された)。前日から使ってよいのは、予告の有無・イベント日か・当日見る指標(どの機種のRB確率を何Gで見るか)だけ。
8. **短く書く。** `判断:` は1〜2行、`避ける:` は0〜1行。ホール節は予告の無い日は5行以内、予告のある日も15行程度まで。過去実績の表を写さない。

### 手本(予告のある日)

```
## 楽園
基準: 機種A・機種B・機種C
予告(<アカウント> <日時>): 「<原文の要旨>」。公約: 指定5機種に必ず1台はてっぺん。
判断: 機種A・機種B・機種C(基準)に、機種D・機種Eを足す(公約の指定機種)。
避ける: 機種F(機械割が低く、6台で稼働が伸びない)。
確度は低〜中。同じ系列の過去回は10回で、幅が大きい。
```

### 手本(予告の無い日・蒲田7)

```
## 蒲田7
基準: 機種A・機種B・機種C
試験枠: 基準の3機種、RB自動候補(末尾の表)。ジャグラーは持ち越し上位の 2101・2105・2110 を外す(仮説、10月 −212)。
判断: 格上げされた方法がまだ無いので、機種は推さない。鉄台2026。
```

## 点検のしかた(人が直すとき・定期タスクが読むとき)

- 基準の行があるか、`判断:` が基準から始まっているか、差し替えた機種に理由があるか。
- 予告の無い日・予告外について、`試験枠:` の行があるか。蒲田7で格上げ前の方法が `判断:` の行に入っていないか。
- `避ける:` の理由が「前日 −◯◯」「前回 −◯◯」になっていないか。
- 本文で台番号を選んでいないか(予告で台が指定された日を除く)。
- 凍結は `判断:` の行・「避ける」を含む行・「ジャグラー候補」表だけを機械的に拾う。凍結前に `venv\Scripts\python.exe -m backtest.prediction_ledger extract <文書>` で抜き出しを確かめる。
