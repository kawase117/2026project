# 検証レポート：モグ玄・ぽこ報告 vs DB実績

**作成日**: 2026-06-02  
**検証対象**: モグ玄（Mogendo）データ、ぽこデータ抽出、蒲田7・蒲田1 DB記録

---

## 概要

各アカウント（モグ玄、ぽこ）の報告データとホールDB記録を照合した結果、**データの性質と信頼性に関する重要な問題が発見されました。**

---

## 発見1: Mogendoデータの日付ズレと信頼性の問題

### 状況
- **Summary レコード**: 24件（蒲田7）
- **Detail レコード**: 205件（蒲田7、63個の異なる日付）

### 問題

**Summary と Detail の日付一致性が非常に低い：**

| マッチ状況 | 件数 | 割合 |
|-----------|------|------|
| 完全一致（0日）| 12 | 50% |
| +1日ズレ | 10 | 42% |
| -1日ズレ | 2 | 8% |

**エラー率が異常に高い（エラー = Summary値との乖離）：**

- **平均エラー**: 196.1%
- **エラー範囲**: 50% ～ 442%
- **最大エラー**: 442%（2026-01-06のデータ）

### 具体例

```
2025-08-18: Summary=123,300 → Detail(同日)=542,400 → Error: +340%
2025-08-19: Summary=131,800 → Detail(-1日)=542,400 → Error: +312%
2025-08-29: Summary=124,300 → Detail(+1日)=94,700  → Error: -24%
```

### 解釈

単純な「翌日報告」仮説では説明がつかない。以下の可能性がある：

1. **データ方法論の違い**
   - Summary = 報告者が手動で記録した「その日の目立った差枚」
   - Detail = DB から自動抽出した「全機種の合計差枚」
   - → 計算基準が異なる可能性

2. **報告粒度の違い**
   - Summary = 「高設定台のみ」の抽出値
   - Detail = 「全台の合計」
   - → 抽出率が理論的には 20-60% 程度と推測（ただし実績が 50-442% なので信頼度低）

3. **データ品質の懸念**
   - 19/24 が日付ズレしている状況は異常
   - エラー率 196% は単なる「日付ズレ」では説明不可
   - **報告方法に一貫性がない可能性が高い**

### 推奨アクション
- **Mogendo Summary の信頼性は低い** と判断
- Detail データのみを使用する、または日付ズレを手動で確認する必要あり
- 「Summary 対象差枚」の計算ロジック（何を「対象」としているのか）を確認

## 発見2: Pocoデータの抽出率が100% = 「全台報告」である可能性

### 状況

**ぽこ報告の差枚とDB実績が 100% 一致：**

| ホール | DB記録 | ぽこ報告 | マッチ率 | 件数 | 抽出率 |
|--------|--------|---------|---------|------|--------|
| 蒲田7 | 188 | 188 | **100%** | 188/188 | **100.0%** |
| 蒲田1 | 141 | 141 | **100%** | 141/141 | TBD |

**具体例**:
```
2025-07-07: ぽこ報告=1,857,400 → DB全体差枚=1,857,400 ✓ 100%
2025-07-08: ぽこ報告=541,700 → DB全体差枚=541,700 ✓ 100%
2025-07-09: ぽこ報告=735,900 → DB全体差枚=735,900 ✓ 100%
（全20サンプルが 100.0% 完全一致）
```

### 解釈

**抽出率 100% は「高設定台のみ選別」ではなく、「ホール全体の日次成績」を報告している意味：**

| 仮説 | 根拠 | 推奨判断 |
|-----|------|---------|
| ぽこ = 「高設定台の報告」 | 報告内容の「仕掛け内容」欄に機種・台番・戦略記載 | 部分的に true |
| ぽこ = 「ホール全体の日次成績」 | 差枚が 100% 一致（全188件） | **強く true** |

**→ ぽこの「差枚」は「高設定台抽出結果」ではなく「全台成績の集計」**

### 含意

ぽこレポーターは 2つの情報を並行して報告している可能性：

1. **「仕掛け内容」欄**: 店側の設定投入戦略の推測（機種、グループ、台番指定など）
2. **「差枚」欄**: その日の全ホール成績（DB記録と完全一致）

つまり、「差枚」は「仕掛け戦略の検証」ではなく、「そのホールのその日の営業成績」を記録している。

### ぽこの信頼性評価

| 項目 | 評価 | 根拠 |
|------|------|------|
| **日付の正確性** | ✅ 優 | 全188件がDB記録に存在、未発見0件 |
| **差枚数の信頼性** | ✅ 優 | DB全体値と 100% 一致 = 報告粒度が一貫している |
| **機種・台番の詳細さ** | ✅ 優 | 仕掛け内容から機種・グループ・台番範囲を特定可能 |
| **戦略情報の精度** | ⚠️ 要確認 | 仕掛け内容が実際のDB記録と合致するか確認が必須 |

## 発見3: データの用途別評価

### モグ玄データ

**用途評価**:
- ❌ 日次成績の照合には不適切（日付ズレが 42-50%, エラー率 196%）
- ❌ 高設定台の抽出精度検証には不適切
- ⚠️ 機種情報の参考 = Detail レコードの機種名の信頼性を確認後に判定

**推奨**:
- Detail テーブルを詳細に確認し、日付ズレパターンを把握した上で有償利用を判断
- Summary データは「定性的な参考資料」程度の扱い

### ぽこデータ

**用途評価**:
- ✅ ホール全体の日次成績記録 = **信頼性高**
- ⚠️ 仕掛け内容の戦略解析 = 内容欄と DB 記録を cross-check 後に判定
- ❌ 「高設定台」の選別精度 = 報告データから直接測定不可（全台差枚のため）

**推奨**:
- ぽこの「差枚」を **DB成績の外部検証データ** として活用可能 ✅
- 「仕掛け内容」（「全→マギレコ, モンハン...」など）が実際の設定配置とどう関連しているかは別途分析が必要

## 次のステップ

### 優先度「高」

1. **Mogendo の日付ズレ原因調査**
   - Summary データの「対象差枚」の計算方法を報告者に確認
   - +1日ズレが大多数（42%）+ 0日一致（50%）の原因を特定
   - 「なぜ半数が日付ズレしているのか」を質問

2. **ぽこ「仕掛け内容」の検証**
   - サンプル日付（例: 2025-07-07）で、「全→マギレコ, モンハン」記載が実際の機種配置と合致しているか spot check
   - 仕掛け記述が「推測」か「事実」か確認

### 優先度「中」

3. **蒲田1 データの補充分析**
   - Mogendo: 蒲田1 は 1件のみ（データ不足、信頼度評価不可）
   - ぽこ: 蒲田1 は 141件（蒲田7 と同等のサンプル数）
   - 蒲田1 も同様の詳細分析を実施

4. **ML学習への活用判断**
   - ぽこデータ = 信頼性高で、戦略情報（仕掛け内容）と紐付け可能
   - 検証2完了後に「ぽこ差枚 + 仕掛け内容」を教師データ候補として検討
