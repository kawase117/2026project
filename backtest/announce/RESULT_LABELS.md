# 結果報告アカウントによる正解ラベル台帳

`announce/*.json` は **予告** を凍結する仕組みで、`source.kind` は "予告" しか受け付けない
（結果報告を予告として登録すると的中率が定義上100%になるため）。
一方で結果報告そのものには別の価値がある。**ホールが実際に何を入れたかの、我々の指標と
独立なラベル**である。これが無いと `zentaikei` の閾値も metric も自己採点しかできない。

したがって結果報告はここに記録する。用途は2つに限る。

1. **指標の校正** — score の順位・閾値が、第三者が全台系と認識した機種を捉えているか
2. **claim type の妥当性検証** — 全台系とニブイチが同じ判定式で測れないことの実証

⚠️ ここに書いたラベルで **予告の的中率を計算してはならない**。結果報告は当日の実績を
見てから書かれており、予告とは情報の非対称がある。予告の採点は announce の
`result` だけで行う。

⚠️ 結果報告アカウントも間違える。ホール側の公式発表ではなく観測者の推定である。
「名指しされなかった＝入っていない」とは限らない（発信者の偽陰性を我々が指標の
偽陽性と呼んでしまう危険がある）。

## この日から出た校正結果

**順位は極めて有効、閾値は緩すぎる。**

- 3ホールで第三者が全台系と認定したのは4機種（楽園2・蒲田1で1・蒲田7で1）。
  **4機種すべてが score rank ≤ 2 に入っていた**（1位 / 2位 / 2位 / 1位）。
- 一方 score ≥ +1,800 を満たした機種は 5+7+5 = **17機種**。適合率 4/17 ≒ 24%。
- 閾値を上下させるより、**「上位2機種」で切るほうがこの日は機能した**。
  ただし n=1日・3ホールなので閾値の変更は行わない
  （README「この指標は変更しない」の趣旨。別指標として並走させること）。

**ニブイチは機種平均では原理的に検出できない、が改めて実証された。**

蒲田1でニブイチと名指しされた4機種のうち、閾値を超えたのはヴヴヴ2（6台）だけ。
東京喰種は20台で rank 8、ネオアイムジャグラーは22台で rank 21、戦国乙女5は10台で rank 23。
**台数が多いニブイチ機種ほど機種平均が薄まって沈む。** `model_named_ratio`
（上位1/N台をホール同分位と比べる）が無ければ全部「外れ」になっていた。
実際、楽園の東京喰種は `model_named` 換算なら rank 16 で外れ、`model_named_ratio` では
excess +1,683 で的中している。

**同じ機種が同日に2ホールでニブイチ指定されている。**
東京喰種が楽園蒲田（31台）と蒲田1（20台）の両方で名指しされた。周年対抗日に
同一機種を両ホールがぶつけた形。単発の観察だが、蒲田駅前の機種選定にホール間の
相互作用がある可能性を示す（`feedback-no-cross-hall-pooling` は「共通法則をプールで
探すな」であって、対抗関係の存在を否定しない）。
