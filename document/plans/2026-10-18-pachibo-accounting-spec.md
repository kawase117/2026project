# 遊技収支帳：収支計算と入力の仕様案

更新日: 2026-10-18。Android実装前の仕様。利用者が現金・貯玉を併用し、台移動数量がほぼ分かることを前提とする。

## 1. 何を収支と呼ぶか

現金収支は「実際の受取現金 − 実際の現金投資」。
評価収支は現金収支に、遊技に伴う貯玉と持ち玉の増減を円換算して加える。
初版の評価基準は口座ごとの交換相当額とし、貸出単価とは分ける。
実際の交換では受取現金を優先し、交換した数量をさらに評価回収に加えない。
再プレイ手数料が数量で徴収される場合は、遊技に使った数量と手数料を合わせた口座減少を費用とする。

1台の式（すべて同じ評価基準で計算）:

`評価収支 = 受取現金 − 現金投資 + 貯玉入庫評価額 − 再プレイ口座減少評価額 + 持出評価額 − 持込評価額`

持込・持出は台移動だけでなく、その記録の外から入る／外へ残す持ち玉を含む。
同じ玉を貯玉入庫と持出に同時に入れない。現金購入で得た玉は現金投資と重ねて費用にしない。
終了時に残っている数量は「交換」「貯玉」「次の台」「その他の持越し」に重複なく振り分ける。
一般景品など円評価できない受取は数量とメモを残し、評価額が決まるまでは評価収支を未確定とする。

## 2. 残高入力は必須にしない

再プレイによる減少、入庫による増加が全件記録されていれば、開始貯玉残高を知らなくても遊技損益は算出できる。
残高不明の口座は「残高未設定」と表示し、収支とは独立して扱う。
開始・終了残高の差で入力する場合は、その間の口座操作が記録済みの操作と重複しないよう、差額を照合に使う。
残高差を各台へ自動で均等配分しない。

## 3. 入力の流れ

| 場面 | 必須入力 | 自動設定・任意入力 |
|---|---|---|
| 開始 | ホール、遊技種別 | 日時は現在、機種・台番号・タグは後から補完可能。レート区分は選ばない |
| 現金追加 | 今回使った円 | 入力前後の合計を表示 |
| 再プレイ追加 | 今回引き出した数量 | 口座を引継ぎ、手数料は設定から提案して確認 |
| 台移動 | 持出数量、次の記録の確認 | 同じホール・種別・口座・営業日を引継ぎ |
| 終了 | 残量ゼロ、または残量の行き先と数量 | 現金交換時のみ実際の受取円を入力 |
| 過去記録 | 営業日と投資・回収または数量明細 | 時刻は不明のまま保存可能 |

投資追加は円と数量を同じ欄で兼用しない。単位を入力欄の横に常時表示する。
終了時に「すべてなくなった」を選ぶことで明示的なゼロを記録する。空欄をゼロに変換しない。
貯玉のみで終える場合、受取現金欄は表示せず、操作の意味から現金回収ゼロを確定する。
換算率未設定でも数量記録を継続できる。終了と評価額確定は別状態にする。

## 4. 台移動の保存・訂正

移動ID、元記録ID、先記録ID、数量、単位、評価率のスナップショットを1件の移動として保存する。
元の持出と先の持込は同じデータから算出し、別々に編集できないようにする。
旧台終了・移動作成・次台開始は1トランザクション。操作IDの一意制約で再送・連打による重複を防ぐ。
確認前のキャンセルでは旧台を遊技中のままにする。
数量訂正は両台を再計算する。移動付き記録の削除は移動の解除・残る台の扱いを確認して一括保存する。
異なる口座・レートへの移動は自動換算せず、実際の交換・再貸出を記録する。

数量不明の場合は移動の存在を保存し、両台の評価収支を未確定にする。
両台を含む集計では内部移動が相殺されるため、その他の入出金・数量が揃えば全体収支は算出可能。
片方だけを機種などで絞り込んだ集計は未確定とする。
未確定台を除いた合計を、何の注記もなく全体の合計として表示しない。

## 5. 計算例と受け入れ条件

以下は架空レート。全例の金額は円。A、Bは同日の別の台。

| ケース | 操作 | 台別評価収支 | 合計評価収支 | 現金収支 |
|---|---|---|---:|---:|
| 現金のみ | 5,000投資、8,000受取 | +3,000 | +3,000 | +3,000 |
| 貯玉のみ（1枚20円） | 300枚引出、500枚入庫 | +4,000 | +4,000 | 0 |
| 混在（1枚20円） | 5,000投資、100枚引出、400枚入庫 | +1,000 | +1,000 | -5,000 |
| 台移動（1枚20円） | Aで10,000投資、600枚をBへ。Bで16,000受取 | A +2,000、B +4,000 | +6,000 | +6,000 |
| 交換と貯玉（1枚20円） | 5,000投資、終了500枚のうち300枚を6,000で交換、200枚入庫 | +5,000 | +5,000 | +1,000 |
| 非等価（1枚=1,000/56円） | 100枚引出、156枚入庫 | +1,000 | +1,000 | 0 |
| 再プレイ手数料（1枚20円） | 遊技用100枚、手数料5枚、150枚入庫 | +900 | +900 | 0 |
| 移動数量不明 | Aで10,000投資、数量不明でBへ。Bで16,000受取 | A・Bとも未確定 | +6,000（両台を含む場合） | +6,000 |

受け入れ条件:

- 既知数量の移動を任意の値へ訂正しても、両台を合算した収支は変わらない。
- 移動数量不明のAだけを抽出したとき、評価収支を0や-10,000と確定表示しない。
- 貯玉開始残高が未設定でも、上表の貯玉のみ・混在を計算できる。
- 交換と貯玉の混在で交換数量をもう一度回収に加えない。
- 終了・評価確定・移行確認の3状態を独立に保持する。

## 6. 換算・表示・旧記録

率は「1,000円につき56枚」のような整数の比として保存し、二進浮動小数による金額誤差を避ける。
計算は有理数または同等の精度を持つ方式で行い、表示時だけ1円へ四捨五入する（負数も絶対値で同じ規則）。
日合計・月合計は丸め前の値を合算してから丸める。表示明細の和との差は「表示丸め差」として明示する。
設定変更で過去の率を更新しない。過去記録の率の訂正は対象と再計算結果を確認して適用する。
記録時に率が未設定ならnullを保持し、後から対象記録へ明示的に割り当てる。

ぱち簿由来の投資・回収は元の金額と意味を保存する。現金か貯玉評価込みか未検証の金額を現金収支と断定しない。
旧記録には「元アプリ収支」という基準を付け、新方式の評価収支との混在を表示する。
利用者が旧記録の基準を確認するまでは、基準ごとの小計を示す。既存の収支額を勝手に換算し直さない。
CSVには収支基準、現金収支、評価収支、評価確定状態、移行確認状態を別列で出力する。
未確定の金額は空欄とし、0円とは区別する。

## 12. 操作性の修正（2026-10-19、利用者の指摘に対応）

ホール・機種は既存記録、保存口座、追加した名前を検索付き一覧にまとめ、記録入力・編集・分析で選択できる。新しい名前は手入力して保存すると再利用可能。設定に機種名テキスト（UTF-8、1行1機種）の一括取り込みを追加した。ネットからの機種マスター自動取得は行わない。catalogに追加分を保持する。
遊技開始・台移動・終了・基本情報編集と、従来/過去日入力に日付・時刻ピッカーを追加。分析の開始日・終了日も日付ピッカーと解除操作に変更。終了が開始より前の場合は保存を拒否し、明細追加と日時更新を同じトランザクションで保存する。経過時間は開始から終了まで（休憩控除なし）。旧durationは消さず、旧時間欄として表示し、明示的に開始・終了を入力した場合だけ分数に更新する。自由記入はメモ欄にまとめた。
RecordEditorで従来記録の投資・回収をそれぞれ円/枚/玉から選べる。数量と交換率から円換算のプレビューを更新し、元の入力数量・単位・交換率・日時をrecord_detailsに保持。recordsの金額は円換算した整数で、数量入力の換算額は1円未満四捨五入。投資と回収の非現金単位の混在は拒否する。新方式の記録でも「円で投資」「玉・メダルで投資」、現金/玉・メダルの回収を明示し、数量の円換算プレビューを追加した。現金交換した数量を回収数量へ重複入力しない説明を表示する。
金額・数量・交換率の欄は数字キーボード、文字フィルター、全角数字正規化、入力中の3桁区切りを共通化。数字・区切り・空白以外の文字を入力フィルターで除外し、保存時に範囲と必須項目を検証する。最初の検証でキーボード指定だけでは貼り付け文字を防げなかったため、明示的なInputFilterを追加して再検証した。

## 13. 開始・終了の操作フローと履歴候補（2026-10-20）

「遊技を開始」から遊技日をカレンダー選択し、遊技種別（スロット初期値）、ホール、機種、数字専用の台番号、開始時刻、任意のタグを入力する。開始に口座選択を要求しない。ホールと種別に対応する登録済み交換率を自動で引き継ぎ、未登録のホールでも現金のみの記録を開始できる。開始・終了時刻には「現在時刻を入力」ボタンを設け、通常の入力では遊技日を繰り返し選択させない。新しい終了記録は同じ遊技日内に限定する。以前の複数日にまたがる記録の編集では元の日時を表示・保持できる。

遊技完了画面に現金投資、玉・メダル投資、現金回収、玉・メダル回収を並べ、ホールの交換率を使って保存後の収支を事前表示する。途中で記録した投資は終了画面で再入力しないよう説明する。4種類の明細、終了時刻、タグ、分析用メモを1トランザクションで保存する。レート未登録時に数量を入力した場合は保存を拒否する。開始後にホールの交換率を登録した場合も、終了時に現在の登録値を参照できる。従来・過去日入力の編集画面も現金と玉・メダルを同時に入力でき、元の入力数量をrecord_detailsに残す。台番号は先頭ゼロを維持する。

ホール候補は最終利用日、機種候補は遊技種別と直近履歴を優先し、通常一覧は先頭20件に絞る。古い名前は検索できる。機種はスロット・パチンコ別に表示し、種別不明のぱち簿由来機種は「未分類」から検索する。ぱち簿の未分類を機種名だけで推測して自動分類しない。分析画面にも遊技種別の条件を追加した。DB/バックアップ形式はv6のまま。
