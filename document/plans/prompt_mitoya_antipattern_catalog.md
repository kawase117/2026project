## 実装

mitoya_theory.md に直接追記する。コードの新規作成は不要。

出力先: `document/mitoya_theory.md` の否定された仮説リスト（#19）の後に追加。

### 追記する内容のテンプレート

各パターンに以下4項目を含める:

```markdown
### パターン N: [パターン名]

**現象**: [このパターンが何を引き起こすか]

**検出方法**: [どうやって検出するか]

**みとや実例**: [具体的な事例と数値]

**対策**: [今後どう防ぐか]
```

### 追記する7パターンの内容

#### パターン1: 鉄台による偽シグナル（台固有性）

**現象**: 末尾や角番で有意な差が出たとき、その大半は恒常的に強い1-2台に依存しており、除外すると消滅する。

**検出方法**: machine_dependency テスト（top2_share 算出 + top2除外再検定）。top2_share ≥ 50% なら個体効果。

**みとや実例**: h_jug 末尾 d4 は top2_share=96%。台674（658-674 の角番1、マイジャグラーV）が d4 全体の 87.3% を担い、674除外で +135→+17 に崩壊。d2 も台642 が 55% を占め除外で +124→+39。

**対策**: 有意結果が出たら必ず台別分解→top2_share算出→除外再検定。みとやではマイジャグ角1/2（台674、台641等）が事実上の鉄台。

#### パターン2: セグメント未分割の全体集計（Simpson's Paradox リスク）

**現象**: 5セグメント分割前の全体集計では、機種タイプの違いが平均化されて真のシグナルが埋もれる。

**検出方法**: セグメント別にランキングを出し、全体と比較。みとやでは Simpson's Paradox 自体は未発生だが、セグメント別に効果の有無が二極化（h_jug は角番◎、v_jug は角番✗）するため、全体集計は無意味。

**みとや実例**: 角番効果はホール全体で有意だが、v_jug/v_nonjug/mixed_805 では非有意。全体の有意性は h_jug/h_nonjug が引き上げているだけ。

**対策**: 必ずセグメント単位で分析。全体集計は参考値のみ。

#### パターン3: 個体効果の交絡（split-half PASS の罠）

**現象**: split-half で前半/後半一致 → 「堅牢」と判断したが、実は特定台が前半も後半も強いだけ。時間的安定性は台固有性の安定性を反映しているだけで、末尾という変数の効果を示すものではない。

**検出方法**: split-half PASS + machine_dependency FAIL の組み合わせパターンを検出。top2_share ≥ 50% なら split-half 結果を信用しない。

**みとや実例**: h_jug d4 は split-half ρ=0.891、regime Top3 重複 2/3 で PASS。しかし machine_dependency で FAIL（top2_share=96%）。

**対策**: 耐久性検証は4テスト体制（split-half, regime, machine_dependency, corner制御）で実施。1テストの PASS だけで判断しない。

#### パターン4: レジーム変化混入

**現象**: 機種入替前後のデータを混合すると、偽のトレンドや効果が出現する。

**検出方法**: レジーム分割テスト（pre/post の Spearman ρ）。ρ < 0.5 なら❌崩壊。

**みとや実例**: h_nonjug debut 序列がレジーム境界（2025-07-07）前後で ρ=0.400。mature が pre=-267→post=+134 に反転。h_jug corner のみ ρ=1.000 で✅安定。

**対策**: 角番以外の効果を主張するときはレジーム分割テストを必須にする。

#### パターン5: DD混入偽陽性（みとや固有）

**現象**: イベント日定義に含まれる DD の下一桁と台番号末尾が交絡し、末尾効果に見える偽陽性が生じる。

**検出方法**: 全日で有意 → 非イベント日限定で再検定。消滅すれば DD 混入。

**みとや実例**: h_nonjug 末尾 d4: 全日 p=0.038（首位）→ 非イベント日 p=0.442（消滅）。DD4/14/24（X_DDS日）の全体底上げが d4 の台番号に乗っていただけ。

**対策**: 末尾分析では必ず非イベント日限定の再検証を行う。特にイベント日定義の DD 下一桁（みとやでは 4 と 7）は末尾との交絡が構造的に起きる。

#### パターン6: 生存バイアス（みとや固有）

**現象**: 経過日数が長い台ほど avg_diff が高い → 「ホールが後から設定を上げた」と解釈するが、実際は好成績の機種だけが長く残った結果。

**検出方法**: survived（181日+生存）と removed（180日以下で撤去）に分類し、debut 期（1-60日）の avg_diff を比較。survived debut > removed debut なら生存バイアス。

**みとや実例**: h_nonjug survived debut=-16.7 vs removed debut=-179.9（MWU p=0.003）。removed 機種は導入初期から成績が悪く早期撤去された。

**対策**: 経過日数効果を主張する際は必ず survived/removed の debut 期比較を行う。

#### パターン7: 主効果なし交互作用のみ（みとや固有）

**現象**: 変数の主効果が非有意（p>0.5）なのに、別の変数との交互作用だけが有意。特定のセル組み合わせが正反対の方向に振れて相殺している。

**検出方法**: 2-way ANOVA で主効果と交互作用を分離。交互作用のみ有意なら、セル分解（全セルの avg_diff + z-score）で駆動セルを特定。

**みとや実例**: mixed_805 debut主効果 p=0.702 だが debut×X_DDS F=10.82, p<0.001。debut(+409)と growth(-169)が X_DDS 日で正反対。

**対策**: 主効果が非有意でも交互作用を見る。逆に、交互作用だけが有意な場合は駆動セルを特定してからルール化する（全フェーズ一律のルールは逆効果になりうる）。
