# 蒲田1・蒲田7 角配置の鏡像関係検証 実装計画

**作成日**: 2026-06-12
**実装担当**: Codex
**プランニング**: Claude

## 背景・目的

蒲田1（マルハンメガシティ2000-蒲田1）と蒲田7（マルハンメガシティ2000-蒲田7）の物理的なフロア配置について、
「角」がどちらの通路を基準にしているか（=フロア全体が左右反転した配置になっているか）を、
統計的手法（差枚パターンの相関分析）で検証する。

**仮説**: ホールの設定投入戦略は通路・角といった物理的なポジションに依存する傾向がある。
両ホールが類似した投入戦略ロジック（例：「通路側の角台に高設定を入れやすい」）を採用しているなら、
台番号位置別の平均差枚パターンを比較したとき、配置が鏡像関係であれば
**X座標を反転させた場合に相関が高くなる**はずである。

カラム: `hall_name, floor, machine_number, X, Y, display_x, display_y, section, section_min, section_max, rank_from_min, rank_from_max`

  蒲田1は2Fのみのため、**今回は両ホールとも2Fのみを対象とする**。
- ※X/Yのスケールが両ホールで異なる（Y最大値77 vs 26）ため、相関分析前に
  **0〜1正規化**が必要。

### 2. 実績データ（差枚）

## 分析方法

### ステップ1: データ結合
各ホールについて `machine_detailed_results` を `machine_number` で `floor_coordinates` とinner join。
台ごとの平均 `diff_coins_normalized`（全期間平均、min_games フィルタは
`utils/filters.py` の `apply_machine_filters` 相当のロジックを流用し `games_normalized >= 1500` 等で適用）を算出。

### ステップ2: 機種構成の交絡除去
台番号位置（X座標）によって設置機種（`machine_name`）の構成が偏っている場合、
機種自体の差枚レンジの違いが配置パターンに混入する。これを除去するため、

```
residual_diff = diff_coins_normalized - mean(diff_coins_normalized by machine_name within same hall)
```

を台レベルで計算し、これを以降の集計に使う（機種内偏差のみを見る）。

### ステップ3: X座標別集計
- 各ホールでXを0〜1に正規化（`X_norm = (X - X_min) / (X_max - X_min)`）。
- X座標（または一定幅のビン、例: 0.05単位）ごとに `residual_diff` の平均を集計し、
  「位置別パターン」の系列を作る。
  - 各ホールのX座標の取りうる値の密度が異なるため、ビン分割（10〜20ビン程度）を推奨。

### ステップ4: 相関比較
- 蒲田1の系列 `S1(x)` と 蒲田7の系列 `S7(x)` を同じビン軸で揃える。
- 以下2パターンでPearson相関を計算:
  - **順方向**: `corr(S1(x), S7(x))`
  - **反転**: `corr(S1(x), S7(1-x))`
- 反転側の相関が順方向より明確に高ければ、X軸方向（通路に対する角の向き）が
  鏡像関係にある可能性を示唆する。
- 同様にY軸についても実施可能だが、Y軸はフロアの奥行き方向で
  両ホールの解釈が異なる可能性が高いため、**まずX軸のみ**で検証し、
  結果次第でY軸・両軸同時反転も追加検討する。

### ステップ5: 有意性・頑健性チェック
- サンプル数（ビン数）が少ない（10〜20点）ため、相関係数だけでなく
  散布図を可視化して目視確認する。
- 期間を分割した場合でも傾向が一致するか（例: 前半/後半で別々に算出し再現性確認）を
  オプションで確認する。

## 出力

- 分析スクリプト: `ml/analysis/kamata_corner_mirror_analysis.py`（新規、再実行可能なスクリプトとして配置）
- 出力:
  - X座標ビン別の `S1(x)` / `S7(x)` / `S7(1-x)` を含むCSV（`ml/experiments/results/` 配下）
  - 散布図（順方向 vs 反転）の画像またはvisualize widget表示
  - 相関係数（順方向/反転）のサマリーをコンソール出力

## 確定事項（2026-06-12 追加検証）

### 前提チェック結果
- **machine_number整合性**: CSV(2F)のmachine_numberは全てDBに存在し、重複もない
  （蒲田1: 360/360一致、蒲田7: 351/351一致）。inner joinによる欠損・偏りリスクはない。
  DB側のみに存在する台（蒲田1: 41台、蒲田7: 364台＝3F等）は分析対象外として除外する。
- **期間**:
  - 蒲田1: 2025-01-01〜2026-06-09（511日）
  - 蒲田7: 2025-07-07〜2026-06-07（334日）
  - 共通期間: 2025-07-07〜2026-06-07
  - **デフォルトは各ホールの全期間**で算出する（残差化により絶対水準は除去されるため）。
    ただしロバスト性チェックとして**共通期間版も追加出力**し、結果が大きく変わらないか確認する。

### games_normalized 下限
- デフォルト **1500**（既存ダッシュボードの信頼性フィルタと同基準）。
- 感度チェックとして 1000 / 2000 でも再計算し、結果の頑健性を確認する（オプション）。

### Xビン数
- 蒲田1: X幅37（3〜39）で360台 → 1Xあたり約9.7台
- 蒲田7: X幅38（1〜38）で351台 → 1Xあたり約9.2台
- **デフォルトは10ビン**から開始。感度チェックとして 8 / 15 / 20 ビンでも算出し、
  結果（順方向 vs 反転の相関差）が安定しているかを確認する。

### 残差化の標準化（リスク1対応）
- ステップ2の機種内偏差 `residual_diff` を算出後、ビン集計した系列 `S1(x)`, `S7(x)` を
  さらに**各ホール内でz-score標準化**（平均0・標準偏差1）してから相関を計算する。
  これにより、残差化後に残るホール間のスケール差・分散差が相関係数に影響しないようにする。

### Y軸反転（リスク不確実時の次手）
- X軸（順方向/反転）に加えて、**Y軸反転**・**X軸+Y軸同時反転**の3パターンも
  同一スクリプト内で最初から算出しておく（追加実装コストが小さいため）。
  - パターンA: `corr(S1(x,y), S7(x,y))`（順方向）
  - パターンB: `corr(S1(x,y), S7(1-x,y))`（X反転）
  - パターンC: `corr(S1(x,y), S7(x,1-y))`（Y反転）
  - パターンD: `corr(S1(x,y), S7(1-x,1-y))`（XY同時反転）
  - Y軸も使う場合は2次元ビン（例: X 5分割 × Y 5分割）でグリッド集計する。
  - まずX軸1次元（パターンA/B）で明確な差が出るか確認し、差が弱い場合に
    2次元グリッド（パターンC/D含む）へ拡張する段階的アプローチとする。

### 欠損・重複チェック（リスク3対応）
- 上記の前提チェックで重複・欠損がないことを確認済みのため、
  実装時の追加対応は不要（スクリプト内でassertを入れて将来のデータ変化を検知する程度で十分）。

## 方針転換（2026-06-12）：X反転検証 → 「角番」特徴量による相関分析

X座標ビン単位の反転相関分析（`mirror_candidate`判定）は**完了済み（結果: False）**。
これに続く分析として、台ごとに「入口/主通路からの物理的な遠さ」を表す
**角番（corner number）** という新しい派生特徴量を定義し、
`residual_diff`（差枚の機種内偏差）および新規追加する`residual_games`
（`games_normalized`の機種内偏差）との相関を見る。

### 角番の定義（フロア別ルール）

#### 蒲田7 2F
- 通常のX方向セクション: `角番 = rank(|X - 18|, 昇順)`（セクション内ランク）
  - 18 はアイル（主通路）中心の近似値。左ブロック(X≤17)・右ブロック(X≥19)を
    単一定数で統一的に扱える。
- 曲がり区間 `2330-2351`: `角番 = 2352 - machine_number`
- Y方向セクション `2001-2010`, `2187-2195`: `角番 = rank(machine_number, 昇順)`

#### 蒲田7 3F
- 通常のX方向セクション: `角番 = rank(|X - 20|, 昇順)`（左ブロック max X=17, 右ブロック min X=23）
- 曲がり区間 `3341-3362`: `角番 = 3363 - machine_number`
- Y方向セクション:
  - `3209-3217`: `角番 = rank(machine_number, 昇順)`（3209が角番1）
  - `3191-3208`: `角番 = rank(machine_number, 降順)`（3208が角番1、蒲田7 2Fの2001-2010とは逆方向）
- 孤立2台セクション `3400-3401`: `角番 = rank(|X - 20|, 昇順)`（3400=角番1, 3401=角番2）。
  サンプル数2のため、分析では参考値扱い・または除外を検討。

#### 蒲田1 2F
- **全31セクション共通の単一ルール**: 各台の座標 `(X, Y)` から
  基準点 `(3, 21)`（実測上の入口位置に相当）への**ユークリッド距離**を計算し、
  `角番 = rank(distance_to_entrance, 昇順)`（セクション内ランク）。
- 検証済み: 20セクション・20台のアンカー全てで一致（左側13台＋右側7台）。
  - 例: `2001-2020`セクションで2001(distance=1.0)が角番1、2020(distance=27.6)が末尾。
  - 例: `2021-2031`セクションで2021(distance=32.2)が角番1、2031(distance=40.7)が末尾。
- 残り11セクション（`1631-1633`, `2162-2166`, `2187-2190`, `2191-2202`, `2203-2212`,
  `2213-2222`, `2223-2235`, `2236-2255`, `2282-2301`, `2302-2316`, `2331-2340`）も
  同一ルールで自動算出する。

### 実装ステップ（追加）

1. `ml/analysis/kamata_corner_mirror_analysis.py` に角番計算関数を追加
   - フロア別ルール（蒲田1 2F: 距離ベース、蒲田7 2F/3F: `|X-C|`ベース＋特殊セクション）を
     設定テーブル（辞書）として持つ。
   - 蒲田7 3Fを新たに分析対象に追加（既存は2Fのみ）。
2. `residual_games`（`games_normalized`の機種内偏差、`compute_machine_residuals`と同様の方法）を追加。
3. 角番 vs `residual_diff` / `residual_games` の相関（Pearson、ホールごと・全期間/2025年H2別）を算出。
4. 蒲田7の曲がり区間 `2330-2351` / `3341-3362` について、2025年H2データで
   角番別の`residual_diff`パターンを他の右ブロック列と目視比較し、
   「両端からの角番投入」の痕跡（U字型など）が見られるか確認（記述的チェック、統計的検定ではない）。
5. `3400-3401`（孤立2台）は集計から除外可能なオプションフラグを用意する。

### 出力（追加）
- `kamata_corner_mirror_kakuban_<hall>_<floor>.csv`: machine_number, section, X, Y, 角番, residual_diff, residual_games
- `kamata_corner_mirror_kakuban_correlation.csv`: hall, floor, period(all/2025H2), corr(角番 vs residual_diff), corr(角番 vs residual_games)

### 安定性判定（2026-06-12 追加）
- 各ビン・各グリッドの `sample_count` をCSVに出力し、空ビンや少数台ビンが支配していないか確認する。
- 感度分析は以下を標準で実行する。
  - 1D Xビン: `8 / 10 / 15 / 20`
  - 2D X/Yグリッド: `3x3 / 4x4 / 5x5`
- 各設定ごとに `forward_corr`, `reflected_corr`, `corr_gap = reflected_corr - forward_corr` を出力し、
  `support_rate` と `sign_consistency_rate` を集計して `stability_score = support_rate * sign_consistency_rate` を算出する。
- 判定基準は保守的に置く。
  - `corr_gap >= 0.10`
  - `support_rate >= 0.75`
  - `all` と `common` の両期間で条件を満たす
  - 以上を満たした場合のみ `mirror_candidate = True` とする
- これを満たさない場合は「鏡像の可能性あり」とは言わず、ノイズ優勢として保留する。
