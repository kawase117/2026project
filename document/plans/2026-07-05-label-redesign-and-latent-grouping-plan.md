# ラベル再設計と潜在グループ発見によるターゲティング精度向上プラン

## 背景

蒲田七・蒲田一を中心に検証してきた高設定台予測は、ホール別個別モデル・機種別グループ化まで
検証した上でAUC 0.551〜0.565で頭打ちになっている（`ml/CLAUDE.md`参照）。Fableとの2ラウンドの
相談を経て、以下が明らかになった。

1. **AUCの壁の正体はモデルの限界ではなくラベルのSN比の限界**。差枚・機械割は「設定差＋試行ノイズ」
   の合成値で、設定間の理論上の期待値差（例：設定6上限114.9%）に対し、日次の実現差枚の分散が
   これを容易に上回る。ノイズが信号を支配する土俵で戦っている。
2. **内部指標（BB確率・RB確率）による設定推定は不採用**。蒲田七・蒲田一はAT機主体で、
   ana-sloのBB確率・RB確率フィールドは欠損が多く実用不可（AT機の内部指標は一部公開されているが
   欠損が多いため「無い」ものとして扱う）。
3. **Top-K累積差枚のような評価軸も不採用**。約700台からのTop-3選択は1日3サンプルしかなく、
   差枚自体の高分散（設定6でも普通に負ける）により統計的検出力が低すぎる。ホール側の意図的な
   ランダム化戦略もあり、真のエッジと偶然を長期間区別できない。
4. **台単位で信頼して使える生データは実質的に「差枚」と「G数」のみ**。これに加え、日付軸の
   特徴量（DD・曜日・末尾・ゾロ目）と回転数異常値（`eda/core.py`の`anomaly_detection`が既存実装）は
   欠損なく使える。晒屋（ぽこ）データは日付・ホール全体差枚との整合性は高信頼だが、個別機種名を
   含む「仕掛け内容」は正確性未検証。

この制約下で、(A) ラベル設計の見直し と (B) 既知グループ（Section・角番・末尾・列・機種）では
説明できない潜在的なグループ構造の発見、の2本柱で改善を狙う。

## Phase A: ラベル再設計

### A-1. G数条件付き事後確率ソフトラベル（本命・最優先）

**目的**: 同じ+3000枚でも2000Gと8000Gでは設定を示唆する強さが違う、という情報を捨てない
ソフトラベルを作る。

**設計**:
1. 機種別（同一機種内、`load_hall_df`の`machine_name`でグループ化）に、`(games, diff)`から
   機械割 `payout_rate = (games*3 + diff) / (games*3)` 相当の値を計算する
   （既存の`payout_rate`計算ロジックがあれば`eda/machine_name_significance_scan.py`の
   `_prepare_frame`を参照して踏襲する。独自の計算式を作らない）
2. 機種内で2成分ガウス混合モデル（低設定群・高設定群）を`payout_rate`に対してEM推定
   （`sklearn.mixture.GaussianMixture(n_components=2)`）。**sklearnの`GaussianMixture.fit()`は
   `sample_weight`を正式サポートしないため、重み付けではなくG数下限フィルタで対応する**：
   EM学習には`games >= 2000`（既存`MIN_GAMES=400`より厳格な閾値）の台日のみを使い、
   閾値未満の台日は学習済み分布への当てはめ（事後確率計算）のみに使う二段構えとする
3. 各台日について「高設定群である事後確率」`p_high_setting`を新ラベルとして出力する

**検証（モデル訓練不要・最も安価）**:
- 既存の`hit_104`ラベル（機械割104%超えの二値ラベル）と`p_high_setting`の相関・一致率を比較
- `(DD, section, 末尾)`のようなセルごとに、日間の`p_high_setting`の分散と`hit_104`の分散を比較する。
  `p_high_setting`の分散が下がっていれば、ラベルのノイズが減っている証拠として採用を進める

**出力**: `ml/experiments/label_redesign/results/{hall}_soft_label_comparison.csv`
（列: `date, machine_name, machine_number, games, diff, payout_rate, hit_104, p_high_setting`）

### A-2. 補助ラベル（マルチタスク・後回し可）

- **C1 完走ラベル**: `games`が機種別の理論上限に近い（上位X%）かどうか。新台除外必須
  （`compute_debut_features`の`pre_existing`/`days_since_debut`でフィルタ）
- **B2 据え置き・連続性ラベル**: 同一台の機種平均差し引き後の残差機械割が2日以上連続で正になる
  頻度を、ランダム仮定での期待発生率とZ検定で比較

A-1の検証結果（ラベル分散が実際に改善するか）を見てから着手するかどうかを判断する。
先に着手しない。

## Phase B: 潜在グループ発見（データ駆動クラスタリング）

**目的**: Section・角番・末尾・列・機種という「人間が事前に決めたグループ」では説明できない、
店の実運用ロジック（設定変更の巡回順・什器の電源系統など）に起因する潜在的な台のグループを
相関クラスタリングで発見する。

**設計**:
1. 台×日の機械割（またはA-1の`p_high_setting`）に対し、以下を順に固定効果として除去した残差を作る:
   `機種` → `section` → `kakuban(rank_from_min)` → `末尾(machine_digit)` → `列`
   （列の定義は座標CSVではなく**台番号ベース**とする：`machine_number // 10`（十の位ブロック、
   例：11〜20番が1列）。`document/instincts/2026-05-25-kamata7-weekday-investment-pattern.yaml`の
   「月曜（一列まるごと）: 1列が例えば11〜20番」という実例に基づく。Sectionは`machine_layout`の
   座標由来の物理配置区分、列は台番号由来の数字区分であり、両者は異なる粒度・異なる情報源の軸
   として併存させる。座標を使う軸はSectionに一本化し、列の実装に座標CSVは使わない）
2. 除去方法は「グループ内平均を引く」逐次デミーニングと、`統計モデル(機械割 ~ C(機種)+C(section)+C(kakuban)+C(末尾)+C(列))`
   の固定効果回帰残差の両方を試し、結果が大きく変わらないことを確認する（頑健性チェック）
3. 台×台の残差相関行列を構築する。同日に存在するペアのみを使い、**共通観測日数が90日未満の
   台ペアは`NaN`として除外する**（相関推定の安定性を優先。既存の`MIN_MACHINE_DAYS_FOR_SPLIT=400`
   は期間分割検証という別文脈の閾値のため流用しない）
4. 階層クラスタリング（Ward法、距離 = `1 - corr`）でクラスタを抽出。クラスタ数はデンドログラムと
   シルエットスコアで決定する
5. 発見されたクラスタと既知グループ（section・kakuban・末尾・列）の一致度をAdjusted Rand Index (ARI)
   で評価する。ARIが低い（＝既知グループと乖離した新しい構造）クラスタが見つかった場合、その
   クラスタに属する台の空間的位置・機種構成を可視化して仮説を立てる

**出力**: `ml/experiments/latent_grouping/results/{hall}_residual_corr_clusters.csv`
（列: `machine_number, section, kakuban, machine_digit, cluster_id`）、
`{hall}_cluster_ari_report.md`（既知グループとのARI比較・解釈メモ）

## 実行順序

1. **Phase A-1のラベル分散比較**（モデル訓練不要、最も安価。まずここから）
2. **Phase Bの残差クラスタリング**（教師なし、既存DBのみで実行可能。A-1と並行可）
3. 1・2で見込みが確認できたら、A-1のソフトラベル + Phase Bで発見した潜在グループを特徴量として
   walk-forward再学習し、既存のAUC 0.551〜0.565と比較する

## 非対象・保留（今回の相談で却下したもの）

- 内部指標（BB確率・RB確率）ベースの設定推定 — AT機主体のため欠損多数で不採用
- Top-K累積差枚評価 — 統計的検出力不足のため不採用
- 晒屋（ぽこ）の「仕掛け内容」を個別機種の学習ラベルに直接使うこと — 正確性未検証のため、
  ホール全体差枚が明確にプラスだった日に限定した寄与シェア（C2）としてのみ将来的に検討
