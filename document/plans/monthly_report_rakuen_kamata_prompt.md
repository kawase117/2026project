# 楽園蒲田 月初レポート 試作プロンプト（PCのClaude Code用）

以下を、リポジトリのフォルダで開いたClaude Codeセッションに貼り付ける。

---

楽園蒲田の「月初レポート」の試作版を作りたい。まず設計をレビューさせ、合意してから実装する。いきなり実装しないこと。

## 目的
直近1か月の差枚・回転数・RB確率・イベント結果報告を重ねて、「来月どの日・どの機種に設定が入りやすいか」の事前確率を出す月次レポート。
次の高設定台そのものの予測ではない。店の設定投入は日単位でランダム化されているので、月次の役割は日次予測にかける事前確率づくり。

## 最初にやること（実装の前）
1. `env-check` と `instinct-import` を実行する（検索語: 楽園蒲田, bonus_rate, 全台系, event, regime）。
2. `backtest-module-guide` を読み、既存モジュールの再実装を避ける。特に `backtest/bonus_rate.py`、`backtest/bonus_specs.py`、`backtest/result_corpus.py`、`backtest/event_days.py`、`backtest/morning.py`。
3. DBのホール名表記（楽園蒲田の正式名）、直近データの最大日、利用できるテーブルを確認して報告する。
4. 既存の何をそのまま呼べるか、何を新規に作る必要があるかを短く報告し、私の承認を待つ。

## 最重要の方針：理想的なデータ以外をはじかない
過去にClaudeは「全台系でも1/4は負けるから全ではない」と否定したり、閾値+1800で足切りしたりして、実際の設定投入を取りこぼしていた。
スマスロATは設定6でも勝率約90%、設定4・5を含む構成ならさらに下がる。負けた台があることは「設定がなかった」根拠にならない。

- 当たり／外れの二値判定にしない。分布と確率で出す。
- 絶対値の閾値（+1800など）で判定しない。同じ機種の通常日の分布に対する倍率・順位で示す。
- 過大な成果（高勝率・高差枚）だけを目立たせない。負け側の分布も同じ表に並べる。
- ただし寛容にしすぎない。基準は「同機種の通常日」で、何でも通る基準にはしない。

## レポートの構成（3層）
**層1 レジーム診断（本体）**
- 楽園蒲田の機種タイプ別（ノーマル／A+AT・BT／AT）に、直近1か月の機種ごとの状態を出す。
- 設定の推定は、設定1〜6の事後確率で出す。「設定4以上の確率」のように確率で示す。スペックは `bonus_specs.py`。
- ボーナス確率で判別できるのはノーマル・BT・A+ATのみ。AT機は機種ごとに有効性（相関r）をゲートする。r が負の機種は使わない。
- RBの扱いは `bonus_rate.py` に従う（ノーマル機はRB、AT機はBB+RB）。
- 差枚はG数の分散を含む。必ず機械割(pp)と並べる。
- 自機種の過去ベースラインとの比較は2標本比率検定。
- 勝率は、機種・設定別の期待勝率と並べる（設定6でも約1割は負ける前提）。

**層2 イベント実績**
- `document/registry/EVENT_DAYS.jsonl` の楽園蒲田分（約81件）と `EVENT_RESULT_LINKS.jsonl` を使う。
- 結果発表の【全台】等の公表は、差枚の分位点（p10/p25/中央値）と勝率で、機種・設定別の期待分布と並べて見る。足切りしない。
- イベント効果は、通常日からの分布のずれ（勝率差・機械割差・RB確率差）で測る。
- 日数が少ないものは、同曜日の通常日から引き直す並べ替え検定にする（t値は使わない）。n=1は効果量を出さず、日付の記録として載せる。
- イベント日は必ずホール別。他ホールの値を借りない。
- 公表は店に都合のいい選択でもある。「公表された＝入っていた」「未公表＝入っていない」とは扱わない。

**層3 来月の事前確率**
- ホール×機種×日条件（DD・曜日・イベント日）の事前確率に変換する。
- 粒度は「来月どの日・どの機種を狙うか」。台単位の翌日予測はしない。

## 守ること
- 全数値に n と信頼区間を付ける。
- 月次は確定した最終データだけで作る。途中データ（サイトセブン等）は使わない（途中の高RBは最終で平均に回帰する）。
- 評価はウォークフォワード（月tまでで月t+1を評価）。キャリブレーションを見て、AUCだけで判断しない。
- 多重検定に注意し、本数を決めてから回す（`prereg`）。Bonferroni等で補正する。
- 結果発表を、翌日以降の予測の入力特徴量にしない（事後情報なのでリークになる）。使い道は①正解ラベル ②ホール別イベント実績の算出。
- last_digit型の違い（TEXT/INTEGER）、weekday_nthは `daily_hall_summary` から取る、など `CLAUDE.md` と `database/CLAUDE.md` の注意に従う。
- 新規スクリプトは `backtest/` に追加する。既存関数を優先して呼ぶ。
- Python は `venv\Scripts\python.exe` を使う。

## 実装の分担
