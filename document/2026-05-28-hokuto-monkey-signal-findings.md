# スマスロ北斗の拳・モンキーターンV シグナル分析結果

**作成日:** 2026-05-28  
**対象ホール:** マルハンメガシティ2000-蒲田7  
**対象機種:** スマスロ北斗の拳（2F）、モンキーターンV（2F）  
**使用スクリプト:** `signal_machine_correlation_analysis.py`、`signal_multi_tail_2fn.py`、`signal_accuracy_2fn.py`

---

## 1. 分析視点

### 1.1 前提：3つの分析は異なる問いを立てている

| 分析 | 問い | 答えの粒度 |
|------|------|----------|
| `signal_machine_correlation` | シグナル末尾は平均的に他機種より良いか？ | グループ比較（平均差） |
| `signal_multi_tail_2fn` | シグナル末尾がTHE BEST末尾か？ | ピンポイント識別 |
| `signal_accuracy_2fn` | 北斗ベスト末尾が2FN最優秀末尾と一致するか？ | 北斗単体の予測精度 |

前者が成立しても後者は難しい。これらの結果が「矛盾するように見える」場合があるが、問いが違うため矛盾ではない。

---

### 1.2 RB閾値の訂正：1/300 → 1/258

旧来の閾値 `rb_prob > 1/300 = 0.003333` には重大な欠陥があった。

| 機種 | 設定 | 理論RB確率 | 旧閾値との比較 |
|------|------|-----------|--------------|
| モンキー | 1 | 1/299 = 0.003344 | **閾値を超える（最低設定が発火）** |
| モンキー | 2 | 1/295 = 0.003390 | 同上 |
| 北斗 | 3 | 1/297 = 0.003367 | 発火（設定3） |
| 両機種 | 4+ | 1/258 = 0.003876 | 発火 ← 本来の目標 |

モンキー設定1（最低設定）が毎日シグナルを発火させ続けた結果、シグナル発動率が83.7%に膨らんでいた。  
正しい閾値は **`rb_prob > 1/258`（設定4以上）**。

**閾値修正の効果：**

| 指標 | 旧 1/300 | 新 1/258 | 変化 |
|------|---------|---------|------|
| RB signal delta | +65.8枚 | **+77.8枚** | +18% 改善 |
| RB signal p値 | 4.97e-7 | **1.05e-8** | 1桁向上 |
| signal_n（RBのみ） | 124,340 | 35,985 | 71% 削減（ノイズ除去） |
| シグナル発動率 | 83.7% | 73.6% | 10pt 低下（diffのOR条件残存） |

### 1.3 signal_machine_correlation 結果（正しい閾値 1/258）

#### 全体効果

| シグナル種別 | delta | p値 | 備考 |
|------------|-------|-----|------|
| diff_signal_only | +71.8枚 | 8.88e-4 | 差枚>200の末尾 |
| **rb_signal_only** | **+77.8枚** | **1.05e-8** | **最も信頼できる** |
| signal_or | +62.8枚 | 2.88e-3 | どちらかが発火 |

RBシグナルは差枚シグナルを数値・p値ともに上回る。設定の直接指標であるため安定性が高い。

#### 真正性確認（fake_tail_check）

| 指標 | 値 |
|------|---|
| signal_tail_avg_diff | 189.0枚 |
| nonsignal_tail_avg_diff | 126.4枚 |
| delta | **+62.6枚（真正シグナル）** |

シグナル末尾全体に設定が入っており、見せかけのフェイク末尾ではないことが確認された。

### 1.4 signal_multi_tail_2fn 結果（rb quantile 0.90）

#### RB quantile の最適点とクリフ現象

| quantile | single日数 | hit_rate | 備考 |
|----------|-----------|---------|------|
| 0.85 | 1 | 0.0% | 統計的に無意味 |
| **0.90** | **32** | **21.88%** | **唯一の有効点** |
| 0.95 | 32 | 21.88% | 0.90と完全同値 |

RBの日次分布は離散的（distinct値が少ない）ため、quantile 0.85→0.90の間に急崖がある。  
0.875も同様に崩壊する可能性が高い。0.95は0.90と同じ閾値に潰れる。

#### カテゴリ別 hit_rate（rb quantile 0.90）

| category | 説明 | hit_rate | adjusted_lift |
|----------|------|---------|--------------|
| single | 1末尾にシグナル集中 | 21.88% | +118.8%（baseline 2.2倍） |
| multi | 複数末尾にシグナル分散 | 26.5% | +32.5%（baseline 1.3倍） |
| no_signal | シグナルなし | — | — |

#### single 日の曜日別 hit_rate

| 曜日 | n | hit_rate | 解釈 |
|------|---|---------|------|
| **水** | 5 | **60%** | baseline(10%)の6倍 |
| **日** | 5 | **60%** | baseline(10%)の6倍 |
| 土 | 8 | 12.5% | baseline水準 |
| 月 | 5 | 0% | パラドックス（下記参照） |
| 火 | 4 | 0% | — |
| 木 | 2 | 0% | n=2で判断不十分 |
| 金 | 3 | 0% | — |

#### 月曜のパラドックス

signal_machine_correlationでは月曜が最強（delta +182、p=5.8e-5）なのに、  
signal_multi_tailでのsingle hit_rateは0/5=**0%**。

**仮説：月曜はホールが複数末尾に分散投資している。**
- 複数末尾に設定が入る → どの末尾も平均的に良い → correlation は成立
- 1末尾に集中しないため single 条件を満たしにくく → single精度ゼロ
- 実際、月曜は multi が多く、single になりにくい

### 1.5 signal_accuracy_2fn 結果（北斗ベスト末尾の精度）

| 指標 | 値 | baseline | 評価 |
|------|---|---------|------|
| 全体一致率 | 12.42% | 10% | +24.2%リフト（小さいが正） |
| **exact_miss日の補正率** | **6.82%** | 10% | **baselineを下回る** |
| hard_miss日 | 1日/146日 | — | 使える定義でない |
| exact_miss日 | 44日/146日 | — | 分析に使える外れ日 |

2FN MLが外した日（exact_miss 44日）に北斗ベスト末尾を参照しても正解率が6.82%（baseline以下）。  
**北斗は予測外れ日の補正材料として機能しない。**

## 2. 実用視点

### 2.1 当日の運用フロー

```
前日夜 or 当日朝:

Step 1. 翌日の曜日を確認
  - 水曜・日曜 → シグナルが強力に機能する
  - 月曜       → 末尾群は良いが、1末尾絞りには使わない
  - その他     → 補助情報として参照のみ

Step 2. RBシグナルを確認（閾値: rb_prob > 1/258 = 0.003876）
  - 北斗の拳:   末尾ごとの平均RB確率 > 0.003876 の末尾を特定
  - モンキーターンV: 同上
  ※ 1/300（旧閾値）は使わない。モンキー設定1が混入する。

Step 3. signal_multi_tail_2fn でカテゴリを確認
  - category == "single" → 1末尾に集中（使えるシグナル）
  - category == "multi"  → 複数末尾に散在（参考情報）
  - category == "no_signal" → シグナルなし

Step 4. 曜日 × カテゴリで行動を決定（下表）
```

### 2.2 曜日 × カテゴリ別 行動指針

| 曜日 | category | 確信度 | 推奨行動 |
|------|----------|--------|---------|
| **水・日** | **single** | **60%** | **シグナル末尾を最優先で選択** |
| 水・日 | multi | 26.5% | 参考。複数候補の中の有力末尾として扱う |
| **月** | single/multi | — | **末尾絞りに使わない**。correlation効果（+182枚）はあるが1末尾特定不可 |
| 土 | single | 12.5% | 参考程度（baseline水準） |
| 火・木・金 | single | 0% | 使わない |

### 2.3 北斗・モンキーの役割と限界

| 用途 | 可否 | 根拠 |
|------|------|------|
| 末尾グループ全体の優位性確認 | **可** | RBシグナル末尾は平均+77.8枚（p=1.05e-8） |
| 水・日の1末尾ピンポイント選択 | **可（60%）** | single条件 × 水曜or日曜 |
| その他曜日の1末尾ピンポイント選択 | 原則不可 | hit_rate 0〜12.5% |
| MLモデルが外した日の末尾修正 | **不可** | 6.82%（baseline以下） |
| 木曜シグナルの逆張り | **不可** | 旧-64枚はノイズ、現在+9枚でニュートラル |

### 2.4 使い方の具体例

#### 例1：水曜日、single シグナルが末尾6に発生

```
状況: モンキーと北斗のRB確率が末尾6のみ 0.003876 超え (single)
判断: 水曜 × single = 60%精度
行動: 末尾6を最優先で選択
      翌日予測MLの top1 が末尾6なら確信度UP
      MLが別末尾を指していても末尾6を有力候補として残す
```

#### 例2：月曜日、single シグナルが末尾2に発生

```
状況: RBが末尾2に集中（single）
判断: 月曜 × single = 0%（実績）
行動: 末尾2の「末尾グループ全体」は平均的に良い（+182枚期待）
      しかし末尾2がTHE BESTである保証はない
      → 2FN MLの予測を優先し、末尾2は「候補の1つ」として残す程度にとどめる
```

#### 例3：2FN ML が外れた日（exact_miss）の翌日

```
状況: 昨日MLのtop1(末尾5)が外れた。今日の立ち回りに北斗を使いたい
判断: 北斗ベスト末尾での補正は hit_rate 6.82%（baseline以下）
行動: 北斗を補正材料にしない
      代わりに: RB single シグナルを確認（水・日なら60%）
                2FN MLの本日予測を使う
```

#### 例4：木曜日、シグナルが発生

```
状況: 木曜にRBシグナルあり
判断: 旧分析「木曜はデルタ-64枚（逆転）」は誤り（モンキー設定1のノイズ）
行動: 木曜のシグナルは他の平日と同等に扱う（ニュートラル、+9枚）
      ペナルティをかけない
```

### 2.5 シグナル確認のチェックリスト

```
□ RB閾値は 1/258（0.003876）を使っているか？（1/300は禁止）
□ モンキーの設定3は存在しない（1・2・4・5・6のみ）
□ category が single か multi かを確認したか？
□ 今日の曜日は水曜または日曜か？（60%精度の条件）
□ 月曜の場合、1末尾に絞る判断を回避しているか？
□ ML exact_miss 時に北斗で補正しようとしていないか？
□ 木曜にシグナルペナルティをかけていないか？（旧分析は誤り）
```
