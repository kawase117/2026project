## 必須手順（ホールが変わっても毎回この順で。ユーザーに手法を再説明させない）

どのホールで分析するときも、まず `backtest/juggler_carryover.py` を `--hall <ホール名>` で実行する。出力の先頭に出る **[監査]行** を読み、結論の前提として必ず引用する。

1. **スペックを確認する。** 実行すると `find_spec` と `machine_master.csv`（公表値）を自動で照合し、不一致があれば**停止**する。止まったら公表値（なな徹・パチセブン等）で直す。`--allow-spec-mismatch` は原因調査のときだけ使う。**機械割の突き合わせ**（BB・RBから推定した設定分布の機械割と、差枚から出した実測の機械割。実測が1〜2ポイント高いのが共通で、それを超えて外れるなら疑う）で独立に確認する。
2. **推定の対象外を確認する。** 監査行の「推定の対象外」に出た機種は、結論に含まれていない。黙って含めたことにしない。
3. **配置は日付つき（`machine_layout_history`）で結合する。** 配置のエポックが複数あるホール（蒲田1は8/3、楽園は7/6）は、島別の集計が日付ごとの島で正しく出る。配置履歴の無いホール（金時）は島別を出さない。
4. **比較は機種内の自群比で行う（`groups` の[全体]欄にも注意書きが出る）。** ホール全体の「全体比」は、高設定の多い機種に条件を満たす台日が集まるだけで有意に見える（組成の効果）。機種・島それぞれ自身の平均との差を見る。
5. **前半・後半で再現を確認する。** 全期間で有意でも、前半と後半で再現しないなら採用しない（ゴーゴー3の台別定位置は再現せず撤回した）。
6. **期間・除外日・変化点を結論に添える。** ホール別の例外は `config/juggler_analysis.json` に持ち、実行すると**除外日は自動で集計から除かれ、期間内の変化点は[監査]行に出る**（自動では分割しない）。変化点を含む期間では、結論を前後で分けて確認する。結論は直近3か月を主に、境界以降と全期間を並べる。新しい例外が分かったら、このJSONに足す（イベント日・配置は既存の台帳を参照し、複製しない）。
   現在の登録: 蒲田7の7/7（全台設定6の特殊日。ジャグラーの単日phは0.153で全台設定6らしくなく、ジャグラーに当てはまるかは未確認）、蒲田1の8/3配置替え・8/25店長異動・9/1ノーマル投入増、楽園の7/6改装・9/7配置替え・9/14入替。
7. **目的は高設定台の発見。** 順位や据え置きの有無自体でなく、最終的に高設定に繋がる材料かで採否を決める。有意でなくても、小標本なら「効果なし」と断定せず観察を続ける（watching）。
8. **記録する。** 検証済みの結論は `document/registry/HYPOTHESIS_LEDGER.md`（期間つき）に、ユーザーの主張は分析者の仮説と分けて出所つきで残す。

**昇格済みの検定**: 群別集計（`groups`）、候補（`tomorrow`）、答え合わせ（`check`）、前半後半の再現（`splithalf`）、位置の分析（`position`）。**まだ昇格していない検定**（据え置きの隠れマルコフ、台固定θ、型の分離、機械割の突き合わせ）は、本書の「検証結果」にある方法に従って実装し直す必要がある。昇格は予定している（次の課題）。

## 目的

高設定台を、座る前に絞り込む材料を見つけること。順位や据え置きの有無を知ること自体は目的ではない。
分析のたびに「最終的に高設定の発見に繋がるか」で採否を決める。

## 設定投入の考え方(ユーザーの実務知識)

ジャグラーは多くのホールで最大設置数の機種群で、設定示唆がほぼ無い。通常日は設定が入らないホールが多いが、ジャグラーだけ設定が入るホールも珍しくない(ユーザーが解析するホールは別)。
店は「ジャグラーに設定がある」と見せるための目立つ仕掛けが必要だが、あからさまだと傾向を読まれて他の台が回されなくなる。したがって配分は「分かりやすく、ある程度分からない」ものになる。複数のパターンが混在するのが普通で、単純な一律ルールを探すのは筋が悪い。

### 5分類

| 分類 | 内容 |
|---|---|
| ランダム | 過去の結果に依存しない |
| 上げ | 過去の結果が悪かったので設定を上げる |
| 下げ | 過去の結果が良かったので設定を下げる |
| 据え | 過去の設定を翌日にも持ち越す |
| 不発据え | 高設定を入れたが店が思ったより出なかった(RBは出ているがBBが少ない、差枚1000枚以下、BBが設定2以下など)ので据える |

「過去の結果」の単位は台・機種平均・列/島のどれもあり得る。主力機種(みとやではマイジャグラー)の列や島に強い投入傾向があり、その中で特定台の結果に基づく投入もある。期間も前日に限らず、先週一週間低設定だったので翌週上げる、もある。据え置きは台単位で考える。

### 別手法

RB確率の絶対値でなく、同機種内・列内のRB確率の順位を作り、どこが上位になるか、上位傾向は据えるのか下げるのかを見る。

## 用語

- **設定5以上の事後確率(ph)**: 1台1日のBB・RB回数と機種のスペックから、設定5以上である確率を求めたもの。BBとRBは別々の証拠として使い、合算はしない。事前分布は機種ごとに、全台日から独立モデルのEMで推定する(一様事前だと楽観的になる。マイジャグラーVで一様なら662の3日合算が0.92、EM事前なら今日時点で0.25前後)。
- **stay(据え置き確率)**: 隠れマルコフ模型の仮定。各台は毎日、確率 stay で前日の設定を続け、確率 1−stay で設定を引き直す。引き直しは設定配分から抽選するので、偶然の一致は stay に含まれない。stay=0は毎日完全に日替わり。
- **対数尤度の差**: ある仮定のもとで観測データがどれだけ自然かの点数差。プラスならその仮定のほうがデータをよく説明する。2倍して約4を超えると偶然ではない目安、約10以上ははっきりした差。
- **台固定**: 特定の台が、日をまたいで高設定になりやすい（またはなりにくい）という、台ごとの偏り。前日の結果には関係なく、その台が「定位置」であるような状態。**据え置き（前日と同じ設定を続ける）とは別物**で、据え置きは日ごとに入れ替わる中で前日を引き継ぐ性質、台固定は長期間変わらない台ごとの傾向。測り方は、前半の期間の台別の平均ph（高設定になりやすさ）と、後半の期間の平均phが、台の並びとして相関するか（順位相関）。相関があれば台固定の兆候。ただし島の端が低い等の**位置の効果**でも同じ相関が出るので、位置の帯の平均を引いた残差で相関が残るかを必ず確認する（`position`）。
- **自群比**: ある条件の翌日平均 − その条件が属する機種・島自身の翌日平均。全体平均との差は、もともと高設定が多い/少ない機種の差が混ざるので使わない。

### 12a. アウトオブサンプル検証（2026-10-13、みとや・マイジャグラーV）

**やり方**: 8/1〜10/11の各日について、**前日までの履歴だけ**で機種ごとの群平均（前日RB良 × 過去7日の差枚帯。台日が少ない群は機種×RB良）を作り、群平均の高い上位10台を「候補」とする。その日の確定データから出した設定5以上の確率（ph）を、候補とそれ以外で比べる。当日の結果は一切使わない。

| 指標 | 値 |
|---|---|
| 検証日数 | 72日 |
| 候補（上位10）の当日の平均ph | 0.144 |
| それ以外 | 0.103 |
| 差の平均（日単位ブートストラップ90%CI） | **+0.041**（+0.028〜+0.054） |
| 差が正だった日 | 67% |
| 群平均と当日phの順位相関の平均 | +0.121 |

候補は、そうでない台より翌日の高設定の確率が約1.4倍。偶然ではないが、台を決め打てるほど強くはない。単日では外れる日もある（10/10は上位10が0.119、それ以外が0.132で逆転、10/11は0.151対0.070）。

答え合わせの実行: `python -m backtest.juggler_carryover check --date YYYYMMDD`（その日の確定データがDBに入ってから）。

### 21. 楽園のメイン機種（ネオアイムジャグラーEX、66台）の整理（2026-10-13）

楽園のジャグラーは、ネオアイムジャグラーEXが66台と最多（マイジャグラーVは20台）。これまでの結果が散らばっていたので、ネオアイムを軸に整理した（境界 20260801、イベント日は `jug` DD{5,11,15,22,25}）。

| 項目 | 結果 |
|---|---|
| 翌日の高設定確率の平均 | 0.135（通常日0.131／イベント日0.154） |
| 日替わりの持ち越し（前日RB良の自群比） | **見えない。** 全日 -0.009。前半 -0.019（逆向き）、後半 -0.002で再現しない。7日低調も前半 +0.015、後半 -0.004で再現しない |
| 島の端−端以外 | **-0.034（前半）／-0.035（後半）で再現。** イベント日も -0.037／-0.032 |
| 台別の偏りの前半・後半の相関 | +0.35（p=0.028）で再現するが、**位置を除くと -0.03（p=0.56）に消える** = 位置（端が低い）だけで説明できる |
| 候補の予測力（アウトオブサンプル73日） | base 0.000、edge_adj +0.013、**fixed +0.023（+0.012〜+0.035、63%の日で正）**、fixed_carry +0.019（+0.008〜+0.031） |
| 同、通常日（61日） | **fixed +0.027（+0.013〜+0.039、66%）**、fixed_carry +0.024、edge_adj +0.014、base -0.001 |
| 同、イベント日（12日） | **どの案も効かない**（+0.003〜+0.005、区間は0を含む） |
| 前向き検証（10/12） | 順位相関 +0.222、上位10 0.107／それ以外 0.092（差 +0.015） |

- **楽園のネオアイムは「位置型」。** 持ち越しは無く、台ごとの偏りは島の端が低いことで説明できる。それでも、台ごとの過去の平均ph（`fixed`）で候補を作ると、通常日にははっきり効く（+0.027）。端が低い位置の効果を、台ごとの平均が拾うため。
- **この機種では `fixed` が `fixed_carry` よりやや良い**（持ち越しが無いので、持ち越しの係数が雑音になる）。持ち越しが確認できたホール・機種（みとやのマイジャグラーV）では `fixed_carry`、持ち越しが無いホール・機種では `fixed` を使うのが理にかなう。差は小さく（+0.023 と +0.019）、日数が貯まってから既定を切り替える。
- **イベント日（12日）は、候補が効かない。** 日数が少ないので参考。
- 残り: 楽園の配置は7/6にエポックが替わる。台ごとの平均には、配置替え前の古い値が混ざる（配置替えをまたぐ台を除いた再計算は未実施）。

## 限界

- どの群でも、翌日の事後確率が0.5を超える台日は5%以下。上乗せは1.5倍程度で、強い予測ではない。
- 型(上げ・下げ・据え・不発据え)が混在して平均されている。機種・島・台単位で分けるとさらに見える可能性がある。
- 不発の閾値(差枚1000枚、BBが設定2以下)はユーザーの目安で、厳密な定義ではない。変えると結果が変わりうる。
- 事後確率は単日のBB・RBに基づく。単日のBB・RBは偶然のぶれが大きく、日別の相関テストは検出力が足りない(日別相関で「据え置きなし」と誤判定した実例あり)。尤度ベースの模型を使うこと。
- 台ごとに設定が固定されている(日替わりの据え置きではない)場合も、同様の数字が出る。区別は「検証結果 4」で実施済み(マイジャグラーVは日替わり据え置き、ゴーゴー3は台固定)。

## 別スレッドへの引き継ぎ（2026-10-13）

3. 10/13の確定が入ったら同様に `check --date 20261013`（火曜・祝日明けが強いかの確認）。

**次の課題（優先度順）**
- 【実施済み】位置の分析は `position` に昇格し、4ホールに当てた（検証結果 15）。島の端を候補に反映する案も `oos` で比較し、`edge_adj` を `tomorrow`・`check` に採用した（検証結果 16）。
