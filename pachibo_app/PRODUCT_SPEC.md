# 遊技収支帳：現行プロダクト仕様

更新日: 2026-10-21。対象: `pachibo_app/android` のローカル試作版。本文の「現行」は、コードから確認できる動作を指す。公開版の確約ではない。

## 1. 目的と対象

ぱち簿の `.pcb` バックアップから履歴とタグを移し、一台単位の遊技記録を日々入力・見直す Android アプリ。収支、稼働時間、回転数、仕事量を比較して立ち回りを振り返る。記録と分析は端末内で動作し、アカウント登録を前提にしない。遊技の結果から将来の勝利を保証したり、設定を断定したりしない。

記録単位は「一日」ではなく「一台の遊技」。日別成績は同日の台記録と経費を集計して作る。主な利用はスロットで、4円パチンコの仕事量計算にも対応する。低貸しを通常のレート切替対象にせず、必要なら別のホール名として管理する運用を想定する。

## 2. 画面と基本操作

| 画面 | 現行の役割 |
|---|---|
| カレンダー（起動時） | 日付選択、日別・月別収支、当日の記録・イベント表示、遊技の開始・終了・編集・削除への入口 |
| 分析 | 期間・遊技種別・ホール・機種・タグで絞った収支、グラフ、比較表、個別記録への移動 |
| 記録 | 取込記録とアプリ作成記録を一つの日付順一覧で参照。直近100件を表示し、編集・明細訂正・削除へ進む。ホール交換率の登録にも入れる |
| 設定 | テーマ、入力項目の表示、機種一覧の読込、`.pcb`・汎用CSV・pachi-ev-analyzer JSON・アプリ自身のJSON・全データZIPの読込、CSV・JSON・ZIP の保存 |

標準の流れは、カレンダーの日付を選ぶ → 遊技種別（既定はスロット）・ホール・機種・台番号・開始時刻・任意タグを入力して保存 → 終了時に同じ記録を開く → 終了時刻、現金と玉・メダルの投資・回収、任意タグ・メモを入力する。過去日分はカレンダーから後入力できる。開始・終了時刻、台番号、回転数・仕事量は設定で表示を切り替える。

現行の開始・終了画面は一台の通常記録を扱う。台移動の持ち玉連結や個々の投資・回収操作の訂正は、別の明細操作を使う。ぱち簿から取り込んだ過去記録は専用の編集画面を使うため、すべての記録で編集体験が同一とはいえない。

## 3. データと収支

- アプリ作成の遊技はセッション、現金・玉・メダルの操作、台移動を保存する。ぱち簿由来の記録は原本の円換算額と取込元の情報を保つ。画面・分析・統合CSVでは両方を一緒に扱う。
- ホール設定には遊技種別に対応する「円 / 玉・枚」の交換率を登録する。数量を入力した収支は、その数量と換算率から円評価する。現金と玉・メダルを同じ遊技で併用できる。台移動の持ち玉は、両台をまとめる際に投資・回収へ重複計上しない。
- 遊技種別が未分類でも収支を確定できた記録は合計に含める。元の記録種別自体が欠けて要確認の記録、遊技中の記録、換算できない記録は確定収支から除外し、その件数を示す。
- 交通費・情報購入費などは経費として記録できる。対象ホール・機種の指定は任意で、指定されない経費を推測で配賦しない。
- 実収支と仕事量は別の指標。4円パチンコの計算仕事量は、提示された式による回転単価に通常回転数を掛け、記録ごとに円へ四捨五入する。式の入力は等価ボーダーと実際の回転率（ともに250玉あたり）、持ち玉比率（0～100%）、交換率（円/玉）。負の仕事量も保持する。計算条件と交換率は記録へ保存する。手入力の仕事量は分析で計算値と分ける。

## 4. 分析の定義

分析は原則として確定収支の記録を対象とし、既定期間は直近90日。30日・今年・全期間の指定、開始・終了日選択、遊技種別・ホール・機種・タグの絞り込み、タグの AND/OR に対応する。

全体には経費込み収支、遊技と経費の内訳、一台ごと・一日合計の勝率と中央値、回収率、累積収支、最大落ち込み、収支分布、時間当たり収支、回転数、計算仕事量、手入力仕事量を表示する。一日勝率は経費だけの日も含む「確定収支がある日」を分母とする。回収率は投資・回収の分かる遊技に対する回収額÷投資額。時間当たり収支は開始・終了時刻のある遊技だけを使い、対象件数を併記する。

比較軸は月、日、曜日、ホール、機種、ホール×機種、タグ。件数・収支・勝率・回収率・計算回転単価などで並べ替えられる。比較欄に回転数と計算仕事量を表示する。タグを複数付けた記録は各タグ群に現れるため、タグ群の合計を全体合計として足せない。ホール・機種×小標本の成績や事後に選んだ好成績は、将来の優位性の証拠と扱わない。

## 5. 移行、マスター、保存

- `.pcb` を Android 上で直接読み込む。重複IDの同一内容は再登録せず、異なる内容の衝突は上書きせずに読込を取り消す。原本に根拠がない種別は未分類・要確認のまま保持する。`.pcb` への書戻しはしない。
- ホールと機種は履歴から候補を作る。直近90日の利用、最後の利用日、同じホールでの使用を優先し、機種候補はパチンコとスロットを分ける。新機種は手入力、または1行1機種の UTF-8 テキスト取込で増やせる。オンラインの自動機種マスター更新はない。
- 端末内 SQLite が一次保存先。アプリの JSON は復元用、統合 CSV は一覧・分析用、全データ ZIP は JSON・各テーブル CSV・タグ関係・保存済み取込原本・小役カウンタを含む。JSON・ZIPは対象件数と期間を確認してから復元する。Android の保存先選択で Dropbox などを選べる場合はそこへ保存できる。Dropbox への自動同期はない。
- 汎用CSVは列対応と先頭行のプレビュー後に取り込む。日付・投資・回収の列は必須で、ホール・機種・台番号・タグ・メモ・遊技種別・稼働時間・照合用収支は任意。UTF-8とWindows-31J、カンマとタブ区切りに対応し、対応付けない列も見出しと元の値を記録の詳細情報に保存する。pRecordの公式掲載CSVとpachi-ev-analyzerの公開実装CSVの見出しは自動対応候補にする。pachi-ev-analyzerの公開実装JSONは専用入口から元の行とJSON全体を保持して取り込む。元データのないホール・機種は空欄、種別は未分類のままとし、現金・持ち玉の内訳も推測しない。
- 小役カウンタは保存済みの一台記録に任意名で追加し、加算と直前の加算1回の取消しができる。値は端末内DBに即時保存し、JSON・ZIP・統合CSVへ含める。設定判別機能はない。
- カレンダーイベントは単発、毎週の曜日、毎月の指定日、毎月11日・22日に対応し、ホール・イベント名・有効期間を保存する。イベントは収支に加算しない。

## 6. 現行の制限と変更管理

ぱち簿由来の現金・貯玉内訳は原本の円換算額から自動復元できない。古い遊技の時刻・仕事量・回転数も、元データに無ければ補完されない。ぱち簿とアプリ作成記録は表示上まとまるが、編集方式は異なる。過去の交換率が変わった可能性がある記録へ仕事量を追加入力するときは、当時の率を利用者が確認する必要がある。
