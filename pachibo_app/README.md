# 遊技収支帳（試作版）

開発方針を検討するときは、[現行プロダクト仕様](PRODUCT_SPEC.md) → [実装済み機能と検証状況](IMPLEMENTATION_STATUS.md) → [次の開発方針](DEVELOPMENT_ROADMAP.md) の順に参照してください。2026-10-18 の初期計画は変更前の提案を含みます。

Android で遊技履歴、台番号、タグ、投資・回収、メモを記録し、ホール・機種・タグ・期間で絞った累積収支と月別収支を表示するアプリです。データは端末内の SQLite に保存します。ぱち簿由来と新規記録を同じカレンダー日計・分析・記録一覧で扱います。CSV・JSON・全データZIPには両方の記録を含めます。

## ぱち簿からの移行

アプリの「設定」→「ぱち簿 .pcb を読み込む」でバックアップを直接選びます。同じバックアップの再取り込みでは同じ履歴 ID を重複登録しません。同じ ID の内容が異なる場合は上書きせず、取り込み全体を取り消します。読み込み後、履歴件数とタグを確認してください。

起動時はカレンダーを表示し、タブは「カレンダー・分析・記録」の順です。カレンダーで選んだ日から遊技を開始し、同じ入力画面を開き直して終了時刻と収支を入力します。終了済みの通常の一台記録も同じ画面で開いて訂正できます。カレンダーに登録した遊技はタップして削除できます。記録タブは、ぱち簿からの取込分と新規記録を一つの日付順一覧で閲覧・訂正・削除するための画面です。カレンダーの日計・月計と分析は両方式を合算します。開始操作はカレンダーに置いています。設定の「表示」から端末設定に合わせる／ライト／ダークを選べます。

`.pcb` の構造は公開仕様ではありません。個人のバックアップを使って、記録の `type=1` と CSV の遊技履歴の対応を検証しました。まずホールマスターの換算値と記録の換算値が一方だけ一致するときに種別を割り当てます。そこから同じバックアップ内でスロット・パチンコの一方だけに現れる過去の換算値を学習し、現在のホール設定と異なる記録にも適用します。同じ機種 ID の一意の判定も引き継ぎます。両種別に現れる換算値や根拠のない記録は「未分類」として保持し、編集できます。既存の未分類記録は同じ `.pcb` を再取り込みすると、未編集の内容が完全一致した場合だけ種別を補完します。`type` が欠けても投資・回収が揃う履歴は「要確認」として取り込みます。日付が不正な履歴、`type=2/3` とその他の型欠損エントリは完全 CSV の `items.csv` に残します。

換算値が0などで遊技種別を特定できない記録もあります。「雑費／経費」のような遊技に伴う支出は全体収支に含め、特定ホール・機種へは推測で配賦しません。`type` 自体が欠ける要確認記録は、換算値などから遊技種別を推定できても集計から外します。換算値だけから全バックアップの遊技種別を決めつけず、各バックアップ内の明確な記録で検証します。

## 分析

グラフは円と日付の目盛りを表示し、表示幅を自動または±3万・5万・10万円から選べます。指定幅を超える値があれば全体が見えるよう自動拡張します。曜日別の集計と、ホール・機種・タグなどを件数・収支・勝率・回収率で並べ替える比較を追加しました。回収率は確定した遊技の回収額÷投資額で、投資額0円なら算出不可と表示します。経費と台移動の持ち玉は投資・回収へ重複計上しません。台移動を含む機種別回収率は参考値として扱います。

回転数と仕事量は任意入力です。4円パチンコでは、通常回転数・等価ボーダー・回転率（どちらも250玉あたり）・持ち玉比率（%）・記録の交換率から回転単価と仕事量を計算できます。回転単価は `(1/等価ボーダー - 1/回転率) × 250 × 交換率 - (1 - 持ち玉比率) × (1/回転率) × 250 × (4 - 交換率)`、仕事量は回転単価×通常回転数で、円に四捨五入して記録します。計算に用いた値と交換率は記録ごとに保存し、あとからホール設定が変わっても記録済みの値を再計算しません。過去の記録に計算値を付けるときは当時の交換率を確認してください。手入力した仕事量と計算値は分析で分けて表示し、回転数・計算仕事量・加重回転単価をホール、機種、曜日、タグなどで比較できます。実収支から仕事量は推定しません。設定で台番号・時刻・詳細項目の表示を切り替えられます。時刻を隠して新規記録した遊技は内部処理用の時刻を持ちますが、稼働時間の集計には含めません。既に保存した項目は非表示にしても削除されません。

分析画面は直近90日を既定にし、30日・今年・全期間へ切り替えられます。遊技・経費・経費込み収支を分け、一台ごとと一日トータルの勝率、中央値、日別累積の最大落ち込み、収支分布、時間当たり収支を表示します。日別勝率は確定収支のある日を分母とし、同日の遊技と経費を合算します。経費だけの日も分母に含みます。月・日・ホール・機種・ホール×機種・タグの各集計から元記録を開けます。月別・ホール別・機種別には遊技時間、時刻が分かる件数、時間当たり収支を併記します。10件未満の集計は参考値と表示します。勝ち履歴は将来の勝率や期待値の推定ではありません。

「雑費／経費」は経費として全体収支へ含めます。記録編集画面では他の経費も指定でき、対象ホールと対象機種を任意で設定できます。対象を指定しない経費は「割当先なし」にまとめ、特定ホール・機種へ推測で配賦しません。タグ別では複数タグの記録が重複します。時間当たり収支は開始・終了時刻が分かる遊技記録だけで計算し、経費を含めません。時刻がない記録が多い集計は時間当たり収支の代表性に注意が必要です。経費だけの集計では一台ごとの中央値を「該当なし」と表示します。

ぱち簿の `.pcb` に有効な開始・終了時刻がある場合は分析用に取り込みます。以前の版で取り込んだ同じ `.pcb` を再度読み込むと、既存の編集内容を保ちながら不足する時刻を補完します。

## 完全 CSV の作成

PC 上でリポジトリの仮想環境を使い、次を実行します。

```powershell
$pcb='path/to/file.pcb'
$out='path/to/complete-export.zip'
& 'venv\Scripts\python.exe' 'pachibo_app\tools\import_pachibo.py' $pcb --output $out
```

ZIP 内の `items.csv` はバックアップから復元できた **全 item と全 item フィールド**を列として含みます。解決できたホール名・機種名・タグ名、合計投資・回収・収支も追加します。マスタの全フィールドを `tags.csv`、`halls.csv`、`machines.csv` に、その他の保存キーを `other_settings.csv` に分けて収録します。各 CSV は UTF-8 BOM 付きです。`audit.json` には件数と文字数不一致項目を、`android_import.json` にはアプリ用の遊技履歴を収録します。

CSV の `tag_ids` と `tag_names` は `|` 区切りです。タグ名には `|` が使われている可能性があるため、厳密な関係は `tag0`、`tag1` などの ID と `tags.csv` で参照してください。元の `tag` 数値もそのまま残します。

## Android ビルド

カレンダーの「＋ イベント登録」から、指定日の単発、毎週の曜日、毎月の指定日、毎月11日・22日をホールごとに登録できます。繰り返しには開始日と任意の終了日を設定できます。開催日の印はカレンダーに表示され、日付の明細から編集・削除できます。イベントは収支計算に含まず、バックアップJSONと完全ZIPの `calendar_events.csv` に保存します。ボタン操作には端末の触覚設定に従う短いフィードバックを付けています。

Android Studio で `pachibo_app/android` を開いて `app` をビルドします。Android SDK 36、JDK 17 以上が必要です。ローカルで `assembleDebug` の成功を確認済みです。デバッグ APK は `android/app/build/outputs/apk/debug/app-debug.apk` にできます。

全データZIP・JSONの保存とJSONの読み込みはAndroidのファイル選択画面を使います。Dropboxなどが保存先として表示される端末では、そのサービスを選べます。入力項目の表示設定もJSON・ZIPに保存し、復元時に引き継ぎます。自動バックアップ・端末間の自動同期は未実装です。

## 現時点の制約

- ぱち簿由来の記録とアプリで作った記録は保存形式と編集処理が異なります。カレンダー・分析・記録一覧には一つの収支として表示します。取り込んだ記録を遊技中に戻すことはできません。過去の台移動を含む新規記録の収支訂正は明細画面で行います。
- ぱち簿の投資・回収欄は原本の円換算額として保存します。現金と貯玉の内訳や使用枚数を通常の記録と同じ明細へ自動移行していません。編集画面には「内訳不明の円換算額」として表示し、現金と玉・メダルの追加入力とは別に扱います。
- 遊技種別未分類の記録も、収支が確定していれば合計に含めます。`.pcb` で遊技らしいが `type` が欠ける記録は要確認として集計から外し、原記録とエクスポートに残します。交換率がない新規記録は計算待ちとして扱います。
- ぱち簿の開始・終了時刻が欠ける記録は時間当たり収支の対象外です。種別未確定・要確認記録も残ります。
- `.pcb` への書き戻しは行いません。アプリ独自の JSON で全記録とタグをバックアップできます。
- `.pcb` の換算値から過去の設定値は読めますが、それを現在のホール交換率として自動登録しません。設定変更や過去の入力方法を判別できないためです。種別を一意に判定できない記録も推測しません。
- `.pcb` の全保存項目を収録した CSV 一式は PC のツールで生成します。アプリの CSV と JSON はアプリが管理する記録項目を保持します。
- 実機操作は未確認です。導入前にバックアップと取り込み件数を確認してください。

## Google Play 公開前に必要な作業

無料利用と買い切りの広告解除、広告を置く場所、購入復元の方針は [RELEASE_MONETIZATION_PLAN.md](RELEASE_MONETIZATION_PLAN.md) に整理しました。広告SDKと課金処理は試作版にはまだ組み込んでいません。

2026-10-20 時点の試作版は `targetSdk 35`、デバッグ APK、`versionCode 1` であり、公開用ビルドと公開申請は行っていません。Google Play の通常 Android アプリ向け新規公開要件は API 36 以上なので、挙動を再検証しながら更新する必要があります。ストア用の Android App Bundle、署名、アプリ情報、プライバシーポリシー、Data safety の記載、実機テストも必要です。個人デベロッパーアカウントの作成時期によってはクローズドテスト要件もあります。

公開前には、両方式の編集をさらに揃え、ぱち簿の原本金額を保持したまま訂正できる操作を実機で検証する必要があります。

参考: [Google Play 対象 API 要件](https://developer.android.com/google/play/requirements/target-sdk)、[Data safety とプライバシーポリシー](https://support.google.com/googleplay/android-developer/answer/10144311)、[個人アカウントのテスト要件](https://support.google.com/googleplay/android-developer/answer/14151465)。
